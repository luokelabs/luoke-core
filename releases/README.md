# releases/ — 每次发布留在仓库里的东西

由 `tools/release.py` 生成，一个发布号一个目录（V1 §7）：

- `evidence/<任务>.<模型>.<参数哈希>.json`：评测汇总（配件版本、组合、分数、硬性条目、延迟、评测集哈希、机器、日期、命令）；`evidence/raw/` 是配件评测程序自己写的逐条结果（输入法的语料不进来）。
- `diff.md`：和上一个发布的差异报告。
- `release.json`：发布清单（模型逐文件哈希、引擎包、主控 DMG 及下载地址）。

配方本身在 `recipes/<发布号>.json`；DMG、引擎包等产物在 `build.noindex/release/<发布号>/`（不进仓库；.noindex 让 Spotlight 不索引，这些副本不会按 bundle id 登记进 LaunchServices）。

## 三档在三台机器上评（2026-10-15 起的做法）

脚本一次只在本机起实验室实例，所以 16 档在 16 GB 测试机、32 档在 32 GB 测试机、128 档在开发机 各跑一次 `--stage eval --tiers <档>`（远端用 rsync 过去的仓库副本，`.luoke-commit` 记提交），然后把远端的 `releases/<发布号>/evidence/`（含 `raw/`）拷回本机同一个目录再跑 diff 及之后的阶段。汇总文件名带评测时的档（`<任务>.<组合>.<档>.json`），`load_evidence` 按（任务, 组合键, 档）区分，所以同一任务同一模型在不同档、不同机器上的记录互不覆盖；共用的组合（输入法的打分、记忆打字）只在最大的档上跑一次即可，但分开跑也行，各档一条记录。给 diff 当"上一个发布"的合集见 `baseline-all-2026-10-14/`。
