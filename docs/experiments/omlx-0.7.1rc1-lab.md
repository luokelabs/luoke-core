## 换引擎前要改的（已在分支 claude/engine-071-prep，4368bc8）

1. **采样默认值**：rc1 发现模型时，给没存过采样设置的模型存一份推荐值（这次 model_settings.json 里 Qwen 是 top_k 20、top_p 0.95），请求里没写的字段就用它。主控只发 temperature、top_p，不发 top_k，所以非 0 温度的任务（`luoke-mail.draft` 0.3 / 0.9）会悄悄多一个 top_k 20。改成请求里一定写 top_k（底座参数里没写就是 0 = 不用 top-k）。0.7.0 本来就收 top_k、请求里的值优先（0 也算）、默认就是 0，所以在现在的引擎上不变。
2. **第一条生成现编内核**：rc1 启动后第一条生成首个 token 慢约 2.2 s（2.67 s 对热了以后的 0.46 s）。冒烟检查量的就是第一条，prefill 只量出 116 tok/s（实际约 3900），而主控的后台估时、打断判断都用这个数。冒烟检查改成先空跑一条 1 个 token 的，新的 rc1 冒烟量出 2391 tok/s（冒烟的提示比上面那条短，所以低一些）。每次引擎重启后的第一条用户请求仍会慢这 2 s 左右。
   冒烟记录多一个 `method`（测量方法版本，现在是 2；审阅 #7 时提出）：已经测过的机器存的是旧量法的数，按组合缓存就永远不重测，修复对已装的用户不生效。没有 `method` 或版本更低的记录在下次启动时重测一次，重测之前后台估时按配方的速度。**换装到已经在用的实例后是行为变化**：一台 M3 Pro 36 GB（beta0）上 9B 的 prefill 从 50 变成实测值（配方 230），后台估时变短、打断判断跟着变，要记进试用日志。
3. **标记测试本身**：后台和"请求中引擎崩溃"两条用 `luoke_items: 8`，可分拣的批大小现在是 1，两条都在主控门口被拒、根本走不到要测的路（0.7.0 上也一样）；扫描还把 run/hub.sock 当成读不了的泄露。改成 1 条、跳过 socket 以后，所有路都走到了。

## 正式换引擎时还要做的

- 发布脚本 engine 阶段：拷 0.7.1 正式版（或这次验过的 rc1）、重签、公证、许可清单和 GPL 源码包。
- 配方升 `engine.version`；已装用户经升级路径重新下引擎包。
- 三档重评全部任务（本机 / 16 GB 测试机 / 32 GB 测试机）：MLX 0.32.2 → 0.32.4 改了数值，这次只验了 0.8B 的速度和嵌入，没验底座（9B、26B）的质量。
- 嵌入：配方里给本档的 `digup.embed` 加上 `image_batch` / `audio_batch` 等，打开图片和声音；`luoke_core/worker/vendor/embedding_gemma2/` 那时可以删（工作进程会自动用引擎包自己的）。
- 换到 0.7.1 以后各档在 M1（16 GB 测试机）上再测一遍打分延迟和单条查询延迟（digup 要 M1 上 p90 < 100 ms）。
