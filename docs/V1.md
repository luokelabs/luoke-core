# luoke-core v1 规格

- **版本**：2026-10-10；§2 任务层和 §8 配件接入契约于 2026-10-12 冻结为**对外约定版本 1**（见各节开头）。这是开工用的规格，只写 v1 要做的；理由和长期设计见 [DESIGN.md](DESIGN.md)，术语见 [CONTEXT.md](../CONTEXT.md)。两者冲突时，v1 的范围以本文为准，规则的含义以 DESIGN.md 为准。
- **用户**：负责人和少数社区测试者，他们知道主控是什么。
- **配件**：luoke-mail、螺壳输入法，以及组件配件螺壳记忆（luoke-mem，顶层 ADR 0014）。
- **要验证的三件事**：任务层和派发能不能撑起不止一个配件；16 GB 档上交互式打分和后台批量任务能不能共存；实验室评测和发布的流程走不走得通。
  - 第一件：开发版上 luoke-mail（9 个任务、示例收件箱 44 封）和 luoke-ime（重排、联想）都接通了，开发机上已日常试用（2026-10-13）。
  - 第二件：**能**（2026-10-13，16 GB 测试机（M1）[experiments/coexistence-e2e.md](experiments/coexistence-e2e.md)）：底座只在安静时刻加载、第一次打分的同一秒卸掉、打字期间一条后台都不接、打字停下后按安静时刻恢复；用户回来的代价是第一个键约 1 s。经主控的打字延迟和本机打分进程一样（M1 上 p90 都约 500 ms，socket 只多 3 ms），都达不到输入法在 M4 上定的 150 ms，由输入法按 `slow` 标记决定。后台在 16 GB 上只能在安静时刻慢慢做（分拣每封 50 s）。
  - 第三件：签名公证的流程通了（§7）；评测和配方的发布流程还没走。
- **v1 不做、正式发布前必做的**：见 §11。v1 的"更新"：打开新版安装器就升级（2026-10-16 定，进 beta1）——安装器看清单的 `built_at` 比已装的新，就结束已装的主控、把旧 .app 挪到环境目录 `previous.noindex/`、自己拷进 `~/Applications`，留下 `run/upgrade.json` 交给新主控；新主控启动看到标记就显示升级页：已装应用里版本和清单不一样的、引擎包版本变了的、本档还没有的模型，确认后按清单下载安装（替换前先结束那个应用的进程），用户数据和下载过的模型都不动，登录项路径不变。回退就是装旧 DMG（它的 `built_at` 更老，只会当加装；要回退先「卸载全部」或手动换回 `previous.noindex/` 里的），撤回靠社区公告。

## 1. 主控本体

- `~/Applications/螺壳主控.app`，bundle id **`ai.luoke.core`**（2026-10-13 定，发布后不变；实验室构建 `ai.luoke.core.lab`）和 Team ID 一次定死；每个 macOS 账户各装一份，不要管理员权限。（开发版 2026-10-13：`app/` 是 Swift 的本体，`app/build_app.sh` 打出「螺壳主控.app」——菜单栏状态灯（圆点：正常 / 半圆：后台已暂停 / 叹号：引擎有问题 / 虚线圆：主控没连上）、菜单（底座、正在做什么、后台状态、功耗档、用电池也运行）、设置页（后台、这台 Mac、存储）、导出诊断信息；本体只拉起自带 Python 跑的 `luoke_core`，经 socket 的 `/status`、`/settings`（只认 `luoke-core` 自己的标识）读写；主控进程带 `--parent-watch`，本体没了它几秒内自己退出并停掉引擎。bundle id `ai.luoke.core`。）
- 唯一的登录项。菜单栏状态灯显示：当前底座、正在做什么、功耗档、全机后台状态。
- 主控环境在 `~/Library/Application Support/luoke-core/`：引擎包、模型、配置、socket、PID 文件。与 `~/.luoke` 等配件数据分开。
- 常驻配件由主控在登录时经 `NSWorkspace.openApplication` 启动，异常退出就重启（配件正常退出前会调用 `exiting`）。
- 主控重启即重启引擎；启动时先按 PID 文件结束上次遗留的引擎进程、确认内存回收。
- 设置页：功耗档、用电池时是否运行后台、存储页（每个模型的占用和谁在用，可手动删除）、导出诊断信息。
- 实验室构建：不同的 bundle id，独立的主控环境和 socket 路径，从固定路径读本地配方，可运行未验证的配件版本。不对外分发，正式构建不编译这些路径。**不碰负责人的东西**：只扫自己的配件目录（环境目录里的 `Applications.noindex` 等和 `--accessory-dir`），看不到负责人 `~/Applications`、`~/Library/Input Methods` 里真实装着的配件，也就不跑它们的空闲任务（2026-10-16 gateway 集成测试发现，10-19 用 main 复现：还没迁走的旧「螺壳记忆.app」带着 learn，`{memory}` 指真实的 `~/.luoke/mem.db`）；没设 `LUOKE_HOME` 时不加载主控里带的记忆（2026-10-17 审查）；`HOME` 还是真实主目录时不执行"删配件数据"的卸载（实验室装的配件声明的 `~/.luoke-mail` 之类就是负责人的）。要测删数据或装真配件，把 `HOME` 和 `LUOKE_HOME` 指向测试目录再起。

## 2. 任务层

> **冻结**（2026-10-12，对外约定版本 1）：本节和 §8 是配件据以实现的对外约定。此后只加不改：加字段、加端点、加原因码可以，改含义、改名字、删东西要升版本号，并在 DESIGN §4 / §11 末尾追加修订。主控在每个答复里带 `X-Luoke-Contract: 1`。

**通道**：Unix domain socket，放在主控环境里只有本账户能进的 0700 文件夹。每个请求的请求头带 `X-Luoke-Accessory: <配件名>/<版本>`；主控按配方的任务表核对任务归属，未登记的调用方不受支持。配件的开发构建可用环境变量 `LUOKE_HUB_SOCKET` 改连实验室构建。

**端点**
| 端点 | 作用 |
|---|---|
| `POST /tasks/<任务名>/v1/chat/completions` | 生成任务。OpenAI 格式，一律流式（`stream: false` 拒绝）。答复的 `model` 写实际用的组合 |
| `POST /tasks/<任务名>/v1/score` | 打分任务。输入上下文和候选，返回各自的 log 概率、组合、耗时、前缀缓存是否命中。工作进程按配件保留最近几条前文的 KV 快照（条数是任务参数），前文以其中一条为前缀就复用。不等待加载 |
| `POST /tasks/<任务名>/v1/predict` | 联想任务（2026-10-13 加，只加不改）。输入前文，返回最可能的 k 个开头各续 n 个 token 的续写及其 log 概率——截到标点、字数上限、丢掉标点开头都在主控里做。**过渡保留**：输入法 beta1 起改用下面的 `/v1/continue`，以后主控升约定版本时删 |
| `POST /tasks/<任务名>/v1/continue` | **通用续写**（2026-10-16 加，顶层 ARCHITECTURE §2：怎么截、挑哪几个、什么算有把握归调用方；luoke-ime 草案 bdee2ea 定稿）。请求 `{"context", "k"?, "max_tokens"?, "stop"?}`：前文后面最可能的 `k` 个开头（第一个 token 取概率最高的 k 个），各自贪心续到 `max_tokens` 个 token（含第一个）、或解码文字里出现了 `stop` 里任何一个串（那个 token 照样交回）、或模型结束。`k`、`max_tokens` 的缺省就是任务参数里的上限（`k`、`max_tokens`；没写 `max_tokens` 沿用 `n`），超了或为 0 答 `invalid_request`；`stop` 最多 64 个、每个 1–8 个字。前文处理、前缀快照、不等待加载和打分一样。答复 `{"branches": [{"tokens": [{"text", "logprob"}, ...], "finish": "stop"|"length"|"eos"}, ...], "model", "ms", "cache_hit"}`：`branches` 按第一个 token 的 log 概率从高到低，恰好 k 支；`text` 是增量解码（一个汉字被切成几个字节 token 时前面几个的 `text` 为空，拼成的那个带整个字）。主控不丢、不并、不截任何一支，不判断开头是不是标点 |
| `POST /tasks/<任务名>/v1/embed` | **算向量**（2026-10-16 加，只加不改；10-16 提议、10-19 认可：全生态推理和权重统一归主控，digup 搜索去掉自带模型改调这里，顶层 ADR 0018）。请求 `{"texts": [...]}`：每条是**调用方加好检索提示前缀的整段文字**（digup：查询 `"task: search result \| query: <文字>"`、文档 `"title: <标题> \| text: <正文>"`），主控不加前缀、不分查询和文档。每条按 token 截到任务参数 `max_tokens`（2048，含 `<bos>`、`<eos>`，和 digup 一致），用 `<bos>…<eos>` 包起来算。条数不超过任务参数 `batch`（32）；`max_chars`（32000，每条）和 `max_total_chars`（320000，一次请求的总量）只防过大的请求，不是截断——超了答 `input_too_long`，条数超了、有空串答 `invalid_request`。答复 `{"vectors": [[...], ...], "dims", "model", "vector_space", "ms"}`，顺序同 `texts`。**`vector_space`**（2026-10-16 应 digup 加，只加不改；`GET /tasks` 里嵌入任务也带同一个字段，本档没模型时 `null`）是向量空间标识，例如 `"embeddinggemma-2/1"`：配件拿它判断以前存的向量还能不能和新算的放在一起比——它没变，换了引擎、量化甚至模型，旧向量照样能用；它变了，就只重算向量（不用重读文件）。**只比相等，不解析**（和 `model` 一样不透明）。它由实验室在发布时定：新向量对参考向量集（digup 的 vectors.json）仍然余弦 ≥ 0.999 就不变，否则加一；它变了 `X-Luoke-Tasks-Version` 也变。向量：每个向量满维（768，不截维）、L2 归一化（点积即余弦相似度）、分量是 float16 精度的数。请求等级看请求头 `X-Luoke-Priority`（同生成请求）：**不带按 `background`**（建索引），按后台的规矩接纳——交互中、最近打过字、用电池、过热、功耗档间歇时答 `busy` / `paused`（带 `reason`、`retry_after`），算完按用时歇；搜索时的查询带 `user-waiting`：随时算，算作交互、打断后台工作。`X-Luoke-Allow-Battery: 1` 同生成请求。专用模型（EmbeddingGemma 2，mlx-vlm 加载）跑在主控监管的工作进程里，不走引擎、不排队，配件运行期间常驻（空闲 10 分钟停、下次用到再起，见 §3 专用模型工作进程的生命周期）；没有前缀缓存。不等待加载：正在加载答 `not_ready`。以后要截维、要图片和声音，作为新增字段加（顶层 ADR 0018）|
| `GET /tasks` | 请求方配件自己的任务：任务状态、任务参数；附全机后台状态 |
| `POST /warmup` | 预热租约：立即返回 `{accepted, lease_id, expires_in}` 或 `{accepted: false, code}`；带 `lease_id` 续期，不带或已失效算发起 |
| `PUT /accessory/resident` | 声明要不要作为常驻配件。主控记住每个配件最近一次的声明（持久化，重启也在），登录时按它拉起（入口带 `--resident`）；清单里的 `resident` 只是还没声明过时的默认值。收到声明时主控不当场拉起（配件开启常驻时自己 `open -n -g --args --resident` 起实例），只在登录时拉、异常退出时重启（配件 `exiting` 过的不算异常）；登录时已在运行的不再拉（否则会变成"再次打开"）。（2026-10-13 与 luoke-mail 定） |
| `POST /smoke` | 重新做冒烟检查（2026-10-16 加；只认主控身份）。空体 → `{"started": true}`（后台做，界面轮询 `/status` 的 `smoke`）或 `{"started": false, "running": true}`。首次运行的本机检查页在未通过时给「重新检查」按钮 |
| `POST /uninstall` | 卸载配件（2026-10-16，定进 beta1，见 §6）。只有主控自己的界面能调，配件身份一律 403 `forbidden`。`{"accessory", "data"?, "forget"?, "dry_run"?}`：`dry_run` 只算计划（.app、能删的数据路径、能从记忆里忘掉的条数）；正式卸载时主控先停它的空闲任务、停只有它在用的打分进程，再按 `accessories.uninstall` 的顺序删。**2026-10-16 删掉了 `POST /accessories/luoke-mem/ui`**（顶层 boundary-audit：打开记忆界面由调用方用 LaunchServices 打开 `ai.luoke.memory`，主控不转发）|
| `POST /accessory/exiting` | 配件正常退出前调用 |

**推理字段白名单**：配件只决定消息、输出格式、条目数。主控：按任务参数的"每条目预算 + 固定开销"算输出上限并覆盖 `max_tokens`；条目数不得超过批大小；思考开关、采样、模板参数按任务参数和底座参数覆盖；按底座分词器中和消息里的特殊 token 串；自己校验消息结构，不合法的不转发给引擎；输入超过字符上限直接拒绝。

**调度字段**（请求头）：请求等级（`user-waiting` / `background`）；`allow_battery`（只用于用户亲手启动的批量工作）。取消 = 关闭连接。

**原因码**：开始流式答复前用 HTTP 状态码 + `{code, message, retry_after}`；开始后用终止事件 `luoke.error`（同字段），配件丢弃已收到的部分输出。进度用 SSE 事件 `luoke.progress`。

| 码 | 含义 |
|---|---|
| `needs_user` | 要用户决定，例如内存不够，附占用者名单 |
| `paused` | 全机后台已暂停（只给后台请求），附原因 |
| `busy` | 后台请求遇到交互中、引擎被别的后台工作占用、或功耗档间歇 |
| `interrupted` | 后台请求被打断 |
| `task_unavailable` | 任务状态不是"可用"，附状态和原因 |
| `unsupported` | 这台 Mac 不支持这个任务，附原因 |
| `not_ready` | 打分模型正在加载或在等内存压力恢复 |
| `engine_failed` | 引擎在请求进行中崩溃、超时或加载失败 |
| `deferred` | 只用于预热：暂不预热 |
| `input_too_long` | 输入超过字符上限 |

**任务状态**：可用（可附"在这台 Mac 上较慢"及实测数字）、需下载、下载中（附进度和子原因）、暂停中（附原因，例如熔断、本机检查未通过）、不支持（附原因）。

**线上格式**（冻结的细节，配件照此实现；2026-10-12 按推荐定）

- socket：`~/Library/Application Support/luoke-core/run/hub.sock`（实验室构建：`luoke-core-lab/run/hub.sock`）；上面跑 HTTP/1.1。环境变量 `LUOKE_HUB_SOCKET` 指向别的路径时优先。
- 任务名：`<配件标识>.<任务>`，小写 ASCII、点和连字符，例如 `luoke-mail.triage`、`luoke-ime.rerank`。配件标识就是清单里的 `accessory`（§8）。
- 请求头：`X-Luoke-Accessory: <配件标识>/<版本>`（必填）；`X-Luoke-Priority: user-waiting | background`（生成请求必填；打分请求不填按 `user-waiting`）；`X-Luoke-Allow-Battery: 1`（可选）。
- 生成请求体：OpenAI `chat/completions` 的 `messages`、`response_format`（`json_schema` 或 `json_object`）、`stream: true`；`luoke_items`（整数，条目数，默认 1）。`model`、`max_tokens`、`temperature`、`top_p`、`chat_template_kwargs` 等即使填了也被主控覆盖，不报错。
- 流式答复：标准 SSE。OpenAI 块用 `data: {...}`，结束 `data: [DONE]`；主控自己的事件用 `event:` 行：`event: luoke.progress` + `data: {"stage": "queued" | "loading" | "running", "message": "...", "eta": 秒或 null}`；`event: luoke.error` + `data: {"code", "message", "retry_after"}`，之后连接关闭。
- 开始流式之前的拒绝：HTTP 状态码 + `{"code", "message", "retry_after"}`（`retry_after` 秒，可为 null）。后台请求（生成、嵌入）被 `busy` / `paused` 挡回时还带 `reason`；`busy` 的等待算得出来时（`power_cooldown`、`interactive`、`scored_recently`、`engine_busy`，以及专用模型通道自己的间歇 `lane_busy`）另带 **`retry_after_ms`**（2026-10-17 应 digup 加，只加不改）：精确的毫秒数。`retry_after` 和 `Retry-After` 头是取整的秒（头只能是整数），短的功耗档间歇照它等会白等——例如均衡档一批嵌入做 0.36 s、只需歇 0.36 s，`retry_after` 却是 1；配件有 `retry_after_ms` 就按它等。状态码：400 请求不合法（`code: "invalid_request"`）；403 未登记的配件或任务不归它（`unknown_accessory`），只给主控本体用的接口（`/downloads`、`/settings`、`/endpoint*`、`/smoke`、`/uninstall`、`/accessories/previous`、`/accessories/rollback`）不是本体调的（`forbidden`：自报 luoke-core 之外还按 LOCAL_PEERPID 核对端进程是主控进程的父进程；`/settings`、`/endpoint*` 也认主控自带的命令行 `luoke`，即主控同一个 Python 跑 `-m luoke_core.cli`；2026-10-20 前 `forbidden` 误答 500，前三个只核自报的身份）；404 `task_unavailable`、`unsupported`；413 `input_too_long`；503 `busy`、`paused`、`not_ready`、`needs_user`、`engine_failed`。
- 联想请求体：`{"context": "<前文>", "k": 开头个数（可省，≤ 任务参数 k）, "n": 每个续几个 token（可省，≤ 任务参数 n）}`。答复：`{"continuations": [[文字, 总 log 概率, 第一个 token 的文字, 它的 log 概率], ...], "model", "cache_hit", "ms"}`，最好的在前；把握门槛由配件自己定（是 nats 单位的常数，照规矩放任务参数里由配件读）。
- 打分请求体：`{"context": "<前文>", "candidates": ["<候选>", ...]}`，候选数不超过任务参数的批大小，前文不超过字符上限。答复：`{"logprobs": [每个候选的 log 概率之和], "model": "<组合>", "cache_hit": true | false, "ms": 耗时毫秒}`。
- `GET /tasks` 答复：`{"contract": 1, "hub_version": "...", "tier": "16" | "32" | "128", "background": {"state": "running" | "paused", "reasons": ["battery", ...]}, "tasks": {"<任务名>": {"kind": "generate" | "score" | "predict" | "embed", "main": true | false, "status": "available" | "needs_download" | "downloading" | "paused" | "unsupported", "reason": "..." | null, "progress": 0–1 | null, "slow": {"measured_ms": ..., "threshold_ms": ..., "source": "probe", "date": "..."} | null, "combo": "<组合>" | null, "model_name": "<给人看的模型名>" | null, "params": {...}}}}`。`model_name`（2026-10-20 应 luoke-mail 加，只加不改）只用来显示（例如设置页的"用的模型"），取配方模型的 `label`，没有就取模型目录名；配件不拿它做判断，`combo` 仍然只记录、不解析。`params` 的键由任务表定，配件只读。嵌入任务多一个 `"vector_space": "<向量空间>" | null`（2026-10-16 加，见上面 `/v1/embed` 一行）。打着记忆的主控在顶层多一项 `"luoke_mem": {"path", "version", "python"}`（2026-10-19，见 §8 组件配件；`python` 2026-10-27 应 luoke-audit 加，只加不改）。
- `POST /warmup`：`{"task": "<任务名>", "lease_id": "..."（续期才带）}` → `{"accepted": true, "lease_id", "expires_in"}` 或 `{"accepted": false, "code"}`。
- `PUT /accessory/resident`：`{"resident": true | false}` → `{}`。`POST /accessory/exiting`：空体 → `{}`。
- `PUT /settings`（主控本体用）：`{"power_mode"?, "background_on_battery"?, "tier"?}`，`tier` 是用户选的档（`null` = 按内存算；只能选内存够的档，2026-10-16 加）→ 当前设置。
- `POST /uninstall`（只认 `luoke-core` 身份）：`{"accessory": "<配件标识>", "data": false, "forget": false, "dry_run": false}` → `{"accessory", "name", "type", "bundle_id", "app", "data": [能删的路径], "forget": {"records", "notes"} | null, "memory_needed_by": [...], "dry_run", "removed": [...], "forgot", "cleanup", "errors": [...]}`；没装 400 `{"code": "unsupported"}`。
- **任务参数的版本**（2026-10-13 加，只加不改）：主控每个答复带 `X-Luoke-Tasks-Version: <串>`，`GET /tasks` 里也有 `tasks_version`；配方、档位、模型分配、任何任务参数、引擎版本变了它就变。配件比较上一次看到的值，变了就重读 `GET /tasks`，不要把参数读一次用到底。（为什么：后端换了——以后包括远端引擎——或配方升级后，字符上限、批大小会变。）

## 2c. 检查更新（10-19：没有升级的菜单项，测试者换版本只能自己去下 DMG；本体 `Updater.swift`）

- 菜单「检查更新…」：按这份主控自己的渠道查（GitHub releases 接口，只带 User-Agent，不带机器和用户信息；按页翻到有本渠道的版本为止，每页 100 条、最多 10 页）：内部版去 `luokelabs/luoke-internal-builds` 查 `internal-*`，beta 去 `luokelabs/luoke-releases` 查 `beta*`（10-28 分开，luoke-core#36）；本机版答"由开发者直接换装"，开发版不查。取渠道里最新一版的 `release.json`，`built_at` 比自己的大才算有更新；显示版本号和更新说明（GitHub 发布页）的链接。
- 「升级」：按那一版清单里 `items.hub` 下主控的 DMG → 核大小和 sha256 → `stapler validate` → 只读挂载 → 核里面 .app 的签名（`codesign --verify --deep --strict`、Team ID 是我们的）→ 打开它，走现有的原地升级（§6，旧版进 `previous.noindex`，数据和模型保留，再按新清单更新应用、引擎、模型）。新主控起来后卸下这次挂载、删掉下载的 DMG（`run/update-mount.json`）。下载和核对都在后台线程，界面只显示进度。失败照实分三种说：服务器上找不到 / 连不上更新服务器 / 下下来但核对不过（原来的主控不动）。
- 自动检查：默认开，每天至多一次（主控起来一分钟后、之后每小时看一次到没到时间），只在菜单里显示「有更新：<版本>…」，不自动装；开关在检查更新的窗口里。

**引擎因内存拒绝时先腾出来再试一次**（2026-10-20 16 GB 测试机实测）：oMLX 的预填内存守卫把 MLX 留着的缓冲池（大请求过后留着，最多约内存上限的 1/3，到 512 步、超过门槛才清）也算作占用。16 GB 档上限 10 GB、9B 底座约 6.3 GB，一条大请求过后缓冲池就把"现在占用"顶到 9.5 GB 左右，之后稍长的提示一直被拒（internal-1019 里 topics、thread 被拒了 40 分钟）。主控在流式开始前收到这种拒绝（400、详情含 memory）时，卸掉底座再装回（实测占用 9.5 → 0.55 GB，再装回约 6.3 GB），重试一次；还是放不下才答"内存不够"。**oMLX 在已经开始的流里报的错**（2026-10-22 internal-1022-3 在 16 GB 测试机上抓到：重试的请求开始流式后又被内存守卫中止，流里来一行 `{"error": {"omlx_code": "prefill_memory_aborted"}}`，主控当成答复转给配件、记成成功，配件拿到空答复）：现在这一行不转给配件，按出错结束；是内存的就和开始前的 400 一样按"内存不够"处理（`hub.memory_refused`）。同样的请求序列单独跑 typing 再 topics，占用在 7.3–8.6 GB 之间、没有被拒。

## 2b. 给高级用户的本机端点（顶层 ADR 0014 修订，2026-10-19 定；`luoke_core/endpoint.py`、本体 `EndpointView.swift`）

让 pi 这类自己会配 base_url 的工具改用主控的引擎，不再单独跑一个 oMLX（"体系里不应该有脱离主控的 LLM 运行实例"）。这是主控唯一的 TCP 入口。

- **开关**：设置 → 高级，默认关，不当普通用户功能宣传。设置里 `endpoint_enabled`、`endpoint_port`（默认 17860：避开邮件助手页面的 8765、oMLX 的 8000、Ollama 的 11434、LM Studio 的 1234；开之前探测，被占了往后找 20 个）。实验室构建不开。
- **接口**：OpenAI 兼容，`GET /v1/models`、`POST /v1/chat/completions`（流式和非流式）。请求里的 OpenAI 字段（messages、max_tokens、temperature、top_p、top_k、stop、response_format、tools、tool_choice……）原样转给引擎，`model` 换成引擎里的 id；流式时补上 `stream_options.include_usage`。`/v1/embeddings` 等嵌入任务（luoke-core#5）合进来以后再加。
- **鉴权和本机限制**：`Authorization: Bearer <密钥>`，密钥默认由主控生成，存在主控环境的 `endpoint-key`（0600），不进 settings.json。用户可以自己填任意字符串（例如沿用原来 oMLX 那把，工具配置不用改），也可以留空：空就不校验密钥（10-19 定；这时这台 Mac 上任何程序、任何登录的账户都能用，设置页会提示）。设置页可复制、改、重新生成；socket 上是 `PUT /settings {"endpoint_key": "..."}`。Host 只认 127.0.0.1 / localhost（防 DNS rebinding）；带 `Origin` 头的一律 403（网页调不了）；请求体上限 32 MB。
- **模型**：主控自己这一档的底座（配方里的名字，例如 `gemma-4-26b-8bit`），和用户登记的本机模型 `user/<名字>`。登记：在设置里选一个 MLX 模型文件夹（有 `config.json` 和 `.safetensors`），主控用 APFS 克隆进自己的模型目录 `user-<名字>`（不多占空间，原文件和用户自己引擎的设置不动；不在同一个卷上就放一个指向原目录的链接），登记后重启引擎让它发现。登记的模型不进评测和支持台账，质量由用户自己负责。登记表在主控环境的 `user-models.json`。
- **让路（内存只由主控一处管）**：端点的请求算"用户在等"：打断后台，排在后台前面；打字照旧最优先（打分是单独的进程，预算里一直留着）。用户模型和现在内存里的（底座 + 已经一起放着的）同时放得下（配方给引擎的上限、这台机器真剩下的内存，两道都算，`Hub.fits_alongside`），就**一起加载**（`Engine.load_extra`），底座不动、后台照常（10-19 luoke-top 实测：3 GB 的模型把 26B 底座挤掉了，改的就是这条）。放不下才**独占**：先等手上用另一个模型的请求做完（`Hub.acquire_model`，配件的生成、冒烟检查、预热都走它），再卸掉底座换上（`Engine.load` 会先卸掉别的）；独占时天花板放大到和用户自己 oMLX 的 balanced 档一样（给系统和别的应用留约 8% 内存，3–8 GB，再扣掉常驻的专用模型；`Hub.exclusive_ceiling_gb`），由 oMLX 自己的内存守卫最后把关；比这还大就答 507；换回底座时还原本档预算（10-19 负责人的 Flash-Next 111.55 GB 原先被按底座的 93 GB 挡了）。独占时配件的后台请求答 `busy`（reason `endpoint`）。用户模型闲了 5 分钟就卸掉（一起放着的只卸它；独占的卸完、常驻底座的档再把底座装回来）。
- **记录**：hub.log 每条记一行元数据（模型、是否流式、token 数、耗时、结束原因），不记文字；`state.json` 里按天记请求数和 token 数（留 30 天），设置页显示今天的。
- **命令行 `luoke`**（主控 .app 的 `Contents/Resources/bin/luoke`，用主控自带的 Python 跑 `luoke_core/cli.py`；设置里不再有安装入口（10-23 精简），要用的跑一次 `luoke install-cli`，在 `~/.local/bin/luoke` 放一个指向 `~/Applications/螺壳主控.app/Contents/Resources/bin/luoke` 的链接；"卸载全部"时一起删）：`luoke launch pi [--model <名字>] [-- pi 的参数]` 照 oMLX 的 `omlx launch pi` 做——从主控读端口和密钥（端点没开就打开并说一句），往 pi 的 `models.json` 写一个名叫 `luoke` 的 provider（模型列表取 `/v1/models`，先留一份 `.luoke-backup`，尊重 `PI_CODING_AGENT_DIR`，原有的 omlx、local 等不动），`defaultProvider` 设成它，再 exec `pi --model luoke/<模型>`（去掉自带 Python 的环境变量）；不带 `--model` 时列出来让用户选。`luoke endpoint` 看状态（不印密钥）。以后加 claude、codex、opencode 照这个加。
- **管理接口**（Unix socket，只有主控本体能调）：`GET /endpoint`（状态和密钥）、`POST /endpoint/key`（换密钥）、`POST /endpoint/models {"path", "name"?}`（登记）、`POST /endpoint/models/remove {"name"}`。`GET /status` 里有 `endpoint`（不含密钥）。

## 3. 派发与资源

- **交互中**：任何路径最近 N 秒有过"用户在等"的请求，或有配件发起了预热（续期不算）。**安静时刻**：连续 M 分钟不处于交互中，主控启动后从启动时刻起算。N、M 待实测。
- **后台工作**：后台请求和冒烟检查，同一时间最多一项在引擎里。
- **接纳后台请求**的三个条件：不处于交互中；引擎没被别的后台工作占用（含功耗档间歇）；全机后台状态是运行中，或者暂停原因只有"用电池"而请求带 `allow_battery`。不满足就立即返回 `busy` / `paused` + `retry_after`，不排队。接下后必要时冷加载底座，发进度事件。
- **打断**："用户在等"的请求（含打分）到来时，粗估后台工作剩余时间（剩余 prefill ÷ prefill 速度 + 剩余 token ÷ 解码速度）与打断代价（约 2 秒断开检测 + 最多一个 prefill 块）比较，剩余更短就让它跑完，否则断开，后台请求收到 `interrupted`。主控不保留部分输出，不重试。
- **打分任务与后台共存**（实测 0 已定，见 [experiments/coexistence.md](experiments/coexistence.md) §10）：底座在内存里打字就已受影响，后台一跑打字不可用，而打断要约 11 s，救不了打字。所以三条一起用：任何路径最近 K 分钟有过打分请求就不接新的后台请求（K 取几分钟量级，上线后再调）；16 GB 档的后台工作只在安静时刻做，底座也只在那时加载、用户一回来就卸载（"用户在等"的请求任何时候都能冷加载，但 16 GB 上做完后不常驻，下一条打分请求一到或闲置超时就卸载）；后台请求按硬件档限制输入长度，慢机器上每条请求控制在几十秒以内，配件分段提交。
- **功耗档**：全速 / 均衡 / 静音，管后台工作和本机端点（pi 这类）的请求；打字和配件里手动点了等结果的请求永远全速（ADR 0011，10-22）。间歇实现：每项后台工作结束后，在它占用 GPU 时长的 0 / 1 / 3 倍时间内不接新的后台工作（返回 `busy`）；端点的请求做完，下一条挂着等它用时的同样倍数（最多 10 分钟，`Dispatcher.endpoint_rested`）；静音在 thermalState 到 fair 时暂停后台。默认均衡。
- **电池与温度**：后台默认只在接电源时跑，设置里可改为也运行；低电量模式下后台一律暂停、不预热；thermalState 到 serious 暂停后台。全机后台状态转为已暂停时：原因是电池或低电量的，正在跑的后台工作跑完；原因是过热或等内存的，按打断处理。
- **驻留**：模型用到才加载，闲置超过一个全局时长就卸载；预热租约期内不因闲置卸载——但 16 GB 档上用户一打字（打分或联想请求到来）底座立刻卸载，租约也拦不住（16 GB 测试机实测 2026-10-13：租约让底座在打字期间多留了 5 分钟，机器换页、后台因内存压力暂停）；专用模型在配件运行期间保持加载。
- **专用模型工作进程的生命周期**（打分、联想、嵌入；issue #11，和 luoke-ime 2026-10-20 商定）：空闲 10 分钟（`WORKER_IDLE_SECS`）就停，下次用到再起，重起期间答 `not_ready`、`retry_after` 2 秒；同一个模型重起时沿用探针结果，不再测。起之前看这台机器还剩的内存（Metal 上限减去现在 wired 的，引擎里我们自己的底座算作能让出来的）装不装得下它常驻的占用（配方 `wired_gb`），装不下就不起、答 `not_ready`、`retry_after` 30 秒；内核报内存压力 critical 时全部停掉，30 秒（`WORKER_HOLD_SECS`）内不起。配件照 `retry_after` 退避，这期间没有重排、联想，打字照常。预热请求照样答应，真用到时再看能不能起。
- **内存**：预算 = macOS 默认 GPU 工作集上限 − 余量（别人调高了 wired 上限时取更小的那个），先扣专用模型，再算底座；传给 oMLX 的天花板要倒推：oMLX 实际可用 = (天花板 − 2 GB) × 0.95，底座常驻加最长请求的 KV 必须在这个数以内——这个占用按实验室实测的 wired 峰值写进配方（实测 1：9B 4-bit 文件 5.8 GB，带 8k KV 和打分模型时比空机多 10 GB；gemma 4 经 mlx-vlm 加载约为文件的两倍），不按文件大小估；主控看内存用 `vm_stat` 的 wired（算还剩多少）和内核的压力等级 `kern.memorystatus_vm_pressure_level`（normal / warn / critical），不用 `memory_pressure` 的空闲百分比（受页缓存影响，会误判），也不用 swapouts 增量当压力信号（16 GB 测试机实测 2026-10-13：16 GB 上自己加载底座就会换出几 GB，用它会把自己的后台工作暂停掉）。16 GB 档上底座在内存里时 warn 不算数（这是 (c) 接受的代价），只有 critical 才动；底座不在时的 warn 是别人在挤，照规则办。从不硬挤："等内存"每次现算，后台请求放不下就 `paused`，"用户在等"放不下就 `needs_user` + 占用者名单（看进程列表里的其他 AI 引擎，不读它们的文件）。内存压力 warn：卸载闲置底座、打断后台；critical：当前"用户在等"做完后卸底座，仍不够才卸专用模型；恢复并持续几分钟后才重新加载。永不调高系统 wired 上限。

## 4. 配方（v1 格式）

随主控 .app 发布（`Contents/Resources/recipe.json`），完整性由代码签名保护。主控记录配方版本号，不验签、不拒收旧配方。

| 部分 | 内容 |
|---|---|
| 模型清单 | 文件哈希、上游版本、量化方式、许可、下载地址列表（ModelScope + Hugging Face 两个地址，2026-10-16 定；主控每项先用最大的文件测各地址几秒的稳定吞吐（首字节前的时间不算）、从快的下，几个文件同时下；断了、或者每 30 秒看一次比另一个地址测出来的慢一半以上，就用 Range 续传换过去（luoke-core#24），哈希照旧逐文件核对，测速、选了哪边、换源都记进 hub.log） |
| 发布清单 | 这一班发布车里每样东西（主控 DMG、引擎包、各模型）的版本、大小、sha256、下载地址列表（主控 DMG 和引擎包在 GitHub Releases，模型在 ModelScope；以后加镜像就是多一个地址）。主控按它下载、按哈希核对；首次运行的"下载"一步读它 |
| 引擎包清单 | 版本、哈希、下载地址、内含的 oMLX / Python / mlx / mlx-lm 版本、支持的 macOS 范围、启动清单 |
| 硬件档 | 三档：16 GB（16、18）、32 GB、128 GB（128、256）；边界在这里定 |
| 模型分配 | 每档：底座一条，每个专用模型一条；角色字段 v1 只用"现役"，其余值预留。实测 1（[experiments/tier-bases.md](experiments/tier-bases.md)）定的底座：16 GB 和 32 GB 都是 Qwen3.5-9B 4-bit（16 GB 只在安静时刻加载、用完卸载；32 GB 常驻），128 GB 是 gemma-4-26B-A4B 8-bit（常驻）；配方里放实验室自己量化的版本 |
| 任务表 | 任务属于哪个配件、主要/可选、调用方式（生成/打分）、延迟要求（关卡机器、口径、数值、本机阈值）、每个配件版本在每个组合上的任务参数（与内存有关的按档细分） |
| 底座参数 | 每个组合：思考开关映射、默认采样、`response_format` 写法 |
| 已验证版本 | 每个配件版本在哪些组合上达到及格线，及当时的任务参数 |
| 依据 | 每个"配件版本 × 任务 × 组合"一句结论 + 摘要 + 证据哈希 |
| 预留字段 | `revoked`、`min_hub_version`、签名 |

任务参数包括所有以 token 或 nats 为单位的常数：门槛、奖励、每条目预算、固定开销、批大小、字符上限、是否思考。

## 5. 引擎包

- 钉住版本、一行不改的 oMLX，连同它自带的 Python、mlx、mlx-lm，由实验室用 Developer ID 重签并公证。版本号在其中任一项或启动清单变化时都要变。
- 底座跑在 oMLX 服务里；专用模型跑在主控监管的 mlx-lm 工作进程里（用引擎包的 Python，以库方式调用，不用 `mlx_lm.server`），主控和它之间只用继承的管道或 socketpair，它不监听端口，父进程消失就自行退出。工作进程的 MLX 缓冲要设上限（2026-10-14，luoke-ime 发现：默认上限约等于不限，每次打分的 logits 形状都不同，缓冲只增不减，开发机上 20 小时涨到 8 GB）：`mx.set_cache_limit` 按配方专用模型的 `cache_mb`（1 GB），空闲 30 s 就 `mx.clear_cache()`；实测连续打分约 2.7 GB、空闲约 1.3 GB，p50 慢 1–2 ms，配方里打分模型的 `wired_gb` 按 2.7 记。`ping` 答复带 active / cache / peak MB，供状态和日志核对。
- oMLX 0.7.0 启动清单（逐条实测后写进配方）：独立 `--base-path`（按引擎包版本分目录）；只听 127.0.0.1 随机端口；随机 `--api-key`；`--no-cache`（实测 0：热缓存对真实分拣命中 0%，混合结构模型的缓存块是 2048 token，系统提示词不足一块）；`--no-hf-cache`；`--memory-guard-gb` = 主控预算（必需：balanced 档在 16 GB 上根本不让加载底座；custom 档实际可用 = (天花板 − 2 GB) × 0.95，预算按这个倒推），预算变化时经管理接口更新（实测 2026-10-12，`tools/engine_ceiling_probe.py`：登录 `/admin/api/login` 后 `POST /admin/api/global-settings` 带 `memory_guard_tier: custom` 和 `memory_guard_custom_ceiling_gb`，立即生效，软/硬阈值同时重算；**把天花板降到底座放不下时 oMLX 会立刻卸载底座**，请求返回 507，之后要重新加载；custom 档只算 oMLX 自己的进程，旁边的打分工作进程它看不见，所以专用模型的占用必须由主控从预算里先扣）；日志级别取能通过 §9 标记测试的最高级别；不传 `--mcp-config`；清掉 `HF_*`、`OMLX_*` 环境变量；每次启动前整份重写 `{base_path}/settings.json`。
- 发请求前按 PID 核对监听端口的是自己拉起的子进程。oMLX 内存保护的拒绝、驱逐、全部中止按"内存不够"处理，不计入熔断。
- 熔断：短时间内反复崩溃就停用，相关任务"暂停中"。看门狗按本机实测速度设超时，没有实测时用配方的保守默认值。

## 6. 安装与首次运行

- 一个 DMG：螺壳主控。首次运行：
  1. 预检硬件档、磁盘空间和 macOS 版本（系统要求 macOS 26.2 以上，2026-10-15 定，顶层 ADR 0017：低于发布清单里引擎包一项的 `min_macos` 就停在预检页；内存低于 16 GB 也停在预检页，写明"螺壳需要 16 GB 或更多内存"——2026-10-22 定，8 GB 只跑专用模型是以后的事，加装、升级时不拦）；
  2. 列出可装的配件（luoke-mail、螺壳输入法）供勾选；主要任务在本机不支持的配件，在这里就说明；
  3. 一屏说清要下载的引擎包和模型、合计大小、预计时间，点一次同意；
  4. 下载（分块、续传、哈希校验、临时位置原子改名；计费或受限网络不自动下载：首次运行以后的自动补下遇到这种网络只在设置的「还缺」那一行提示、等用户点「重试」，首次运行、「应用」窗口、换档都是用户点的，照下；2026-10-27 补上，beta1.1）；
  5. 首次冒烟检查：能加载、能输出合法格式、实测本机速度。通过前任务状态"下载中（正在检查）"，失败则"暂停中（本机检查未通过）"并提示导出诊断信息；
  6. 注册登录项，启动常驻配件。
- 装在 `~/Applications`，不碰 `/Applications`，不要管理员密码。
- 开发版的首次运行（2026-10-13，`app/Sources/LuokeCore/FirstRun.swift`）：六步照上面走；"下载"一步：有发布清单（`Resources/release.json`，开发时 `LUOKE_RELEASE`）就让主控按清单真下载——`POST /downloads`（只有主控本体能发起），主控后台线程逐项下（`luoke_core/download.py`：分块、续传、sha256 核对、暂存在模型目录之外、全部核对通过后整体改名；多个地址按顺序试），任务状态变"下载中"带进度，下完重启引擎（oMLX 只在启动时发现模型）再做冒烟检查；本机用 file:// 地址实测过 4.8 GB + 0.4 GB 两项，进度、重启、冒烟、任务变可用都对。没有清单就退回从本机来源目录（`LUOKE_MODEL_SOURCE`，默认 `~/.omlx/models`）放符号链接，不联网；配件只列已知的两个；冒烟检查由主控启动时做，窗口等结果；登录项用 `SMAppService`（未签名时系统可能拒绝）；常驻配件按 bundle id 用 `NSWorkspace` 打开。换成真下载、发布清单和托管位置之后，流程本身不用改。
- **记忆并进主控、`luoke://memory`**（接口；做法见 §10b）（2026-10-16 定进 beta1，顶层 ADR 0014；接口 10-17 定稿）：
  - 不再有单独的「螺壳记忆.app」。主控 .app 里带 luoke-mem 的代码（自带 Python 的 site-packages 里的 `luoke_mem`，按发布钉住的 luoke-mem 提交打进去）和它的清单 `螺壳主控.app/Contents/Resources/memory/luoke-accessory.json`（照 luoke-mem `packaging/accessory.json` 原样拷，配件标识仍是 `luoke-mem`、任务 `luoke-mem.typing`、空闲任务 `learn`、命令 `forget-tool`）。主控把主控 .app 当作"记忆"这个配件的 .app：命令和空闲任务都用 `螺壳主控.app/Contents/Resources/python/bin/python3 -B` 跑清单里的参数，环境同其他配件（PATH、HOME、LUOKE_HUB_SOCKET、PYTHONDONTWRITEBYTECODE）。主控进程本身不 import `luoke_mem`、不读记忆。
  - **打开记忆界面**：`open luoke://memory`；跳到某一条：`open "luoke://memory?note=<编号>"`；打开到「最近记下的」：`open "luoke://memory?view=recent"`（2026-10-17，ADR 0011，luoke-mem 0.16.0 起；两个都带以 note 为准，view 只认 recent）。主控 .app 注册这个 URL scheme，主控没在跑时系统会拉起它。主控收到后起 `python3 -B <清单 entry> [--note <编号>]`（entry 现在是 `-m luoke_mem app`），起完不管：同一时间只有一个界面服务、已有就复用并打开浏览器，由 luoke_mem 自己保证。主控菜单栏「记忆…」走同一条路。取代 `open -b ai.luoke.memory`。
  - **工具怎么判断记忆在不在**：Swift 用 `NSWorkspace.shared.urlForApplication(toOpen: URL(string: "luoke://memory")!)` 不为 nil；Python 看 `~/Applications/螺壳主控.app/Contents/Resources/memory/luoke-accessory.json` 在不在。过渡期（主控还是 beta0 那版）这两样都没有，可以退回 `open -b ai.luoke.memory`；beta1 起不再需要。
  - **结束记忆进程**：主控升级、退出前，对命令行含 `-m luoke_mem` 且解释器是主控自带 Python 的进程发 SIGTERM（等 10 秒，不退再 SIGKILL）；luoke_mem 收到 SIGTERM 要干净退出（页面提示"点这里重新打开"）。只按命令行认，不按"可执行文件在主控 .app 里"认——输入法的个人化组件也跑在主控的 Python 上。
  - **升级**：发现 `~/Applications/螺壳记忆.app`（bundle id `ai.luoke.memory`）就请它的进程退出、挪进主控环境的 `previous.noindex/`（留作回滚）并在新旧两个路径上 `lsregister -u`；mem.db 和 `~/.luoke` 下的东西一概不动；空闲任务记录键 `luoke-mem.learn` 不变。
  - **卸载**：螺壳记忆不再是可单独卸的一项；"同时从记忆里忘掉"用主控自带的 Python 跑清单里的 `forget-tool`；「卸载全部」删主控（连带记忆的代码），mem.db 保留。
  - **发布清单**：不再有 `luoke-mem` 这一项和 `install-mem` 的 DMG；配方的已验证版本里记忆的版本是打进主控的那份。
- **复用本机已有的模型**（团队 issue luoke-core#3，2026-10-16 定进 beta1；`download.reuse_local`）：下载模型前在 `~/.omlx/models`（含下一层组织目录）、Hugging Face 缓存（`$HF_HOME/hub` 或 `~/.cache/huggingface/hub`，`models--<组织>--<dir>/snapshots/*`）、LM Studio（`~/.lmstudio/models`、`~/.cache/lm-studio/models`）找名字等于清单 `dir` 的目录，逐个文件核对大小和 sha256，对上的用 APFS 克隆（`cp -c`，不占额外空间）放进暂存区，没对上的（例如我们自己的 README、LICENSE）照常下载；只读这些目录，不移动、不改原文件；克隆不了（不同的卷）就下载。10-17 在开发机上只读核对：gemma-26B 15 个文件里 13 个对上（26 GB 免下，核哈希 10 s），0.8B 8 个里 6 个；克隆后原文件的 inode、修改时间都没变。
- **占多少空间**（团队 issue luoke-core#2，2026-10-16 定进 beta1）：首次运行的预检页在内存够两个以上底座的机器上（现在只有 128 GB 档：gemma 26 GB 对 9B 5.8 GB）给选「完整」/「省空间」，每项写底座、大小、按哪一档跑，以及配方 `evidence` 里该底座在该档的实测（邮件分拣、清理判断、记忆归纳的分数）；选了省空间就按那一档跑（模型分配、任务参数、预算、评测底线全按它，证据就是那一档的）。本体把选择写进主控的 `settings.json`（`tier`），主控启动按它覆盖内存算的档（只能往省的选，内存不够的档拒绝）；装完在设置页能换，`PUT /settings {"tier"}` 换档后底座没下就按清单下、下完重启引擎，有就直接重启；`/status` 多一个 `memory_tier`。16 / 32 GB 档的机器只有一个底座，不出现这一步。
- 升级（做法 2026-10-16 定，`Installer.swift` 的 `upgrade`、`FirstRun.swift` 的升级模式、`hub.py` 替换 .app 前 `terminate_app_processes`）：见 §1 开头"更新"一句。发布清单多一个 `built_at`（发布脚本写入，秒数），安装器只认它比已装的大；同一版或更老的安装器照旧走加装。
- 卸载配件（做法 2026-10-16 定，`luoke_core/accessories.py`、本体 `Uninstall.swift`）：主控菜单「卸载…」→ 选一个配件或「全部」→ 看清单 → 删。顺序：结束配件进程（按 bundle id，先礼貌退出再强制；输入法先停用输入源，停不掉就请用户去系统设置里移除再回来；macOS 26 起不调 TISDisableInputSource——第三方进程停用不了，只会把本进程的偏好缓存改脏、让后面的检查读错，10-21 在 26.4.1 上复现过删了 .app 留下失效输入源；"还开着没有"一律起新进程 `defaults export com.apple.inputsources` 读；删完再核一次，还在就照实提示去系统设置移除；顺带删 `$TMPDIR/luoke-ime` 和输入法的单实例锁）→ 停它的空闲任务、只有它在用的打分进程 → 可选"忘掉记忆"（下面）→ 勾了删数据才跑它清单 `commands.uninstall`（可选，配件自己的数据收尾，例如邮件助手删钥匙串里的授权码；留着数据就连授权码一起留，重装接着用；失败只提示）→ 可选删数据 → `lsregister -u`、删 .app，连同换装时留在 `previous.noindex` 里的旧版（同名、同 bundle id；issue #14，之前只有「卸载全部」才删）。**能删的数据路径**只认清单 `data` 里只删和配件自己的标识绑定的位置（10-19 定：只认清单声明的、不再猜）：`~/.<accessory>`（例如 `~/.luoke-mail`）、`~/.luoke/<accessory 去掉 luoke- 的部分>`（例如 `~/.luoke/ime`），以及 `~/Library` 下 `Application Support`、`Caches`、`Logs` 里以 accessory 或 bundle id 命名的目录、`Preferences/<bundle id>.plist`、`Containers/<bundle id>`、`HTTPStorages/<bundle id>`、`Saved Application State/<bundle id>.savedState`；不分大小写；上层目录不能是软链接（最后一段是软链接就只删链接）；`mem.db` 及其旁文件、含这类文件的目录永远不删；别的一律静默丢掉（`luoke_core/accessories.own_data_forms`）。「卸载全部」：所有配件（螺壳记忆最后）→ 停主控进程 → 删环境目录（模型、引擎、状态、日志）→ 注销登录项、清设置 → 主控 .app 移到废纸篓 → 退出；记忆文件保留。默认保留用户数据，勾选并看过清单后才删配件声明的数据。记忆不在其中（归用户、由 luoke-mem 管，顶层 ADR 0014）；另有一个默认不勾的选项"同时从记忆里忘掉<配件名>写的 N 条记录和 M 条理解"（条数来自主控装的 luoke-mem 自带 Python 跑 `python3 -m luoke_mem forget-tool <配件标识> --dry-run`，在删配件文件之前跑；0 条或 luoke-mem 没装就不显示），勾了去掉 `--dry-run` 再跑；退出码 1 只提示、不阻止卸载。卸载 luoke-mem 本身：只删 app，不问也不删记忆；别的配件的"记忆…"入口变灰。声明"读写记忆"的配件装上时，主控把 luoke-mem 一起装上并列在同意那一屏。细节见 DESIGN §8。
- **同一个应用的别的副本**（luoke-ime#15，macOS 27 上：卸载时移进废纸篓的旧输入法还登记在 LaunchServices，新装的切不过去、菜单里是灰的）：装配件时在**放新包之前**把同 bundle id 的别的副本（`lsregister -dump` 里登记的、废纸篓里的）都注销（`apps.unregister_other_copies`；先放后注销不管用，系统的绑定不跟着变），卸载后也注销。完成页「切换到螺壳」看 `--select` 的退出码（0.1.11 起：0 切过去了、1 调用失败、3 调用成功但没切过去），3 或 `--status` 报 `other_copies` 时给「重新登记输入法」——`POST /accessories/reregister`（只有主控本体能调）：注销别的副本，结束它在跑的进程（按路径），用 ditto 复制一份新的换上原位并登记（新 inode，系统才认成新记录、重新绑定；同盘挪开再挪回可能还认成原来那条），删掉换下的，然后再切一次。
- **完成页不能被忽略**（10-21 晚定，算缺陷进 beta1）：首次运行、加装、升级做完时，完成页不在前台就以「螺壳主控」的名义发一条系统通知（"螺壳已经升级到 …，点这里看看" / "螺壳装好了…"；第一次会请用户允许主控发通知），点了把完成页摆到最前。通知标题写结果（"螺壳装好了" / "螺壳已升级到 …"），下载有没成的另发一条"<哪一项>没下下来"＋原因。**程序坞图标不跳**（10-22 照 brand 规范改定，原来 10-21 定的一直跳撤掉）。
- **升级时看得见**（10-21 负责人第一次用「检查更新…」：升级窗口没了、菜单栏也没图标，等了一会儿只看到图标；升级页其实开在别的窗口后面，停在"先看看这台 Mac"）：安装器换包的那一分钟开一个小窗口（「正在升级到 …」，换包在后台线程里做）；新主控的窗口用 `orderFrontRegardless` + `NSApp.activate()` 摆到最前（macOS 14 起 `activateIgnoringOtherApps` 不起作用）；升级页跳过"这台 Mac"，直接从"要更新的"开始。
- **窗口和再次打开**（luoke-core#19、#20，2026-10-21）：主控平时只在菜单栏（LSUIElement）。首次运行、升级、加装、卸载、检查更新、主控小窗口开着时临时当普通 App（`NSApp.setActivationPolicy(.regular)`，程序坞和 ⌘Tab 里有），全关了改回只在菜单栏（`AppWindows`）。再次打开主控（访达、启动台、程序坞）：有安装器预选照旧走加装；有开着的窗口就叫到前面；都没有就弹「螺壳主控」小窗口——状态、和菜单一样的入口（记忆、设置、检查更新、导出诊断、配件回到上一版、卸载）、一句"平时在菜单栏右上角"和「打开菜单栏设置」，菜单栏图标认不出、被挤掉或被关掉时也有路。
- **配件回到上一版**（issue #12，2026-10-20 定进 beta1，"认它当时的验证"）：换装时旧版留在 `previous.noindex`（同名、同 bundle id）。主控菜单「配件回到上一版…」列出留有旧版的配件（`GET /accessories/previous`，只有主控自己的界面能调），选一个 → 普通应用先按 bundle id 结束 → `POST /accessories/rollback`：主控核旧版的签名和 bundle id（不运行它）、停它的任务和打分进程、按路径结束剩下的进程（SIGTERM，3 秒后 SIGKILL）；输入法换好以后再结束跑旧代码的进程、用 `open -g` 立刻拉起新包（10-24 和 luoke-ime 定：换包前结束会被系统马上从旧包再拉起，跟着旧包挪进 previous.noindex，一直跑旧代码；升级也照这样）、两处对调（旧版回原处并登记，现在这份进 `previous.noindex` 并注销，再点一次就换回来），不动输入源。**认证**：每一版主控只认它评测过的那一个配件版本，所以主控在装着的配件版本被本版配方认时，把"哪一版发布验证过它、硬性条目过了的任务"记进环境目录的 `verified-history.json`（每个配件留最近 3 个版本）；换回来的版本不在本版配方里时，只要它正是装着的那份、有这条记录，主控就认它，而且只给记录里的任务（别的答 `task_unavailable`）；没有记录的旧版不让换回（列表里说明原因）。本体记住"不要自动再升到换下来的那一版"（UserDefaults `skipAccessoryVersions`），升级页据此跳过；升级页本来就只换比清单旧的配件、不往回降。常驻配件换好后照常拉起。

## 7. 质量与发布

- 每个任务有评测集（20–40 条起，含硬性条目；多步任务用配件自带的评测程序），交到实验室。
- 每个配件版本发布前，在它用到的每个现役组合上：第 1 层硬性条目全过；第 2 层总分不低于底线；第 3 层硬性条目零回退、总分不低于上次减容差、"支持"变"不支持"算回退，看差异报告后放行。
- 质量在一台机器上评；在每代芯片（M1、M4、M5）上回放固定子集，硬性条目不一致就不发布。
- 延迟要求按任务表里写明的机器和口径在实验室把关；用户机器上按本机阈值标"较慢"。
- 发布脚本由负责人手动跑：评测 → 差异报告 → 写配方 → 签名公证（签名前确认一次指纹）→ 出 DMG。私钥不放成普通文件。
  - 签名公证这一步已有（2026-10-13，`tools/release_sign.sh`）：Developer ID Application（Team ID NJQ5W3T9K5，钥匙串里的证书）由内向外签——自带 Python 的可执行文件和所有 `.so` / `.dylib` → 启动器 / 主程序 → .app，hardened runtime + 时间戳；Python 的 entitlements 在 `tools/entitlements-python.plist`（只开 `allow-unsigned-executable-memory`，不关库校验，因为 .app 里所有 Mach-O 都是同一个 Team 签的）；`--notarize` 用 `ditto` 打 zip、`notarytool submit --keychain-profile luoke.ai --wait`、`stapler staple`、`spctl` 校验。用 luoke-mem 0.9.1 的开发版真跑过：公证 Accepted、staple 成功、spctl 报 Notarized Developer ID，签名后自带 Python 和启动器照常跑。主控 .app 同样签过。引擎包（oMLX 副本）用 `--preserve-entitlements` 重签，沿用它自己的 allow-jit / unsigned-executable-memory / disable-library-validation。签好的东西放 build 目录，不替换已装的。
  - 发布脚本已有（2026-10-13，`tools/release.py`，负责人手动跑；本机用试验小底座走通过全部阶段）。阶段按顺序：**评测**（起实验室实例——自己的环境目录和 socket、`--lab --tier` 按档，按 `tools/release_evals.json` 跑配件自带的评测程序：luoke-mail 的 `bench/run_bench.py --hub`、luoke-ime 的 `engines/xiaohe/bench.py --scorer hub`；"组合" = 任务用的模型 + 这一档的任务参数，几档共用就只测一次、按最大的档跑，参数按档不同就各评各的——分拣的 `max_chars` 三档不同，所以三档各评一次；汇总进仓库 `releases/<发布号>/evidence/`，配件程序的逐条结果拷到 `evidence/raw/`，输入法语料不进来）→ **差异报告**（硬性条目零回退、不低于底线、不低于上次减容差、"支持"变"不支持"算回退；底线和容差在评测表里；不过就停下：硬性没过或低于底线不能发，只是回退的看过报告加 `--accept`）→ **写配方** `recipes/<发布号>.json`（已验证版本 = 评测过的配件版本和组合；依据 = 每条一句结论 + 评测集哈希 + 证据哈希 + 机器、日期）→ **引擎包**（拷 oMLX.app、`release_sign.sh --preserve-entitlements` 重签、zip、哈希；旁边生成它带的 Python 包的许可清单）→ **发布清单** `releases/<发布号>/release.json`（模型逐文件哈希；地址按 `--modelscope` / `--github` 填，没给就是本机 file://、标 `local_only`、不能发；模型和引擎包的摘要同时写回配方）→ **打包主控**（配方和清单放进 Resources）→ **签名**（先打印证书的 SHA-256 指纹，确认才签；`--notarize` 公证并 staple）→ **DMG**（`tools/make_dmg.sh`：只读压缩 DMG、签名、公证、staple；主控 DMG 加进清单，打印要上传的文件）。各代芯片上的回放仍是人工；上传不在脚本里。
- 证据记录格式：配件版本、任务、评测集哈希、组合、量化、参数、机器与芯片、日期、逐条结果。逐条结果留在实验室仓库。
- 一个任务在某一档硬性条目没过、别的档过了（2026-10-15 第一例：luoke-mem.typing 的 9B 在 M1 上有一条临界失败、在 M4 上过）：发布脚本写配方时给这个任务填 `tiers`（只列过的档），主控在不在里面的档对它答 `unsupported`（"这一档没通过验证"），配件照"不可用"处理；不放松硬性条目，也不因此把整个任务拿掉。各代芯片结果不一致仍按上一条处理：不发布，先弄清楚。

## 8. 配件接入契约（v1 子集）

> **冻结**（2026-10-12，对外约定版本 1）：同 §2 的冻结规则。

- 签名公证的 .app，同一个 Team ID；安装路径由配件类型决定（应用在 `~/Applications`，输入法在 `~/Library/Input Methods`），bundle id、Team ID、安装路径一旦发布不变。Python 部分自带 Python，尽量只用标准库。
- 不注册自己的登录项；需要常驻就调 `resident`，正常退出前调 `exiting`。系统拉起的配件（输入法）例外：不声明常驻、不计异常退出，装好后由主控引导用户手动添加输入源：完成页给「打开键盘设置」和步骤（输入源 → 编辑… → + → 简体中文 → 螺壳 → 添加），一句说明苹果那句"能看到你输入的所有内容"的提醒，并照实说输入法不联网、默认把打的字记进本机记忆、在哪关（措辞由 luoke-ime 按顶层 ADR 0013 定）。只在 `--status` 答 `not_registered`（系统还没收录）时调一次输入法的 `--register`，让螺壳早点出现在「编辑… → +」的列表里——0.1.9 起它在 macOS 26 上只注册、不请求启用（luoke-ime 9315c0b）；更早的版本没有 `--status`，也就不会调。早先的 `--register` 在 macOS 26 上会让系统设置弹出"允许「Luoke」启用「Luoke 螺壳」？"，但负责人在 32 GB 测试机（26.5.1）上亲手点了两次「允许」都没加上（luoke-ime 10-20 实测；干净账户上是否一样未验证），弹出来反倒误导用户；完成页每秒问一次输入法的 `--status`（0.1.9 起，状态 `not_registered` / `not_added` / `added_not_selectable` / `ready`；旧版没有这个命令就退回读 `com.apple.inputsources` 的启用列表，读前先同步），到 `ready` 就给「切换到螺壳」按钮（用户在向导里点的才调 `--select`，不在后台切）和一个试着打 nihao 的输入框（issue #13、luoke-ime#13，和 luoke-ime 2026-10-20 商定）。
- 组件配件（luoke-mem）：打在主控 .app 里（§6「记忆并进主控」，顶层 ADR 0014），不单独装、不常驻、不声明数据；清单在 `Contents/Resources/memory/`，里面声明卸载用的 `forget-tool`。**可以有后台的模型任务**（顶层 ADR 0015：关于用户的理解由 luoke-mem 在安静时刻经主控用模型归纳）：像其他配件一样在清单的 `tasks` 里声明、交评测集、进配方，现在是 `luoke-mem.typing`、`luoke-mem.topics`（generate，只走 background；参数见配方），登记成**空闲任务**（下一条）。读写记忆的配件用主控里那份 luoke_mem（10-19 定，luoke-mem 牵头）：`GET /tasks` 的答复顶层有 `"luoke_mem": {"path": <主控 .app 里自带 Python 的 site-packages>, "version"}`（只有打着记忆的主控才有；实验室、开发版没有），工具每次新起进程时问一次、插到 `sys.path` 最前面再 import；不带 Python 的工具（例如 Swift 写的体检）用 `"python"`（主控 .app 自带的解释器）跑 `-I -B -m luoke_mem …`，不从 `path` 往上推布局；主控不在或太旧就退回自带的兜底那份。发布时只核兜底那份的版本不比钉住的 luoke-mem 新。打开记忆界面用 `luoke://memory`。
- 只通过任务层用模型，请求头自报标识；不点名模型，不提供选模型的界面；代码里不写死随模型变化的常数，全部从 `GET /tasks` 读，答复里的 `X-Luoke-Tasks-Version` 变了就重读；按字符上限截短、按批大小分批、报条目数。`combo`（答复的 `model`）是不透明标签，只记录、不解析；`tier` 只能展示，不能据此决定行为——配件不需要知道算力怎么配置（以后换成远端引擎也一样，见 research/remote-engine.md）。
- 生成请求一律流式；处理全部原因码；按 `retry_after` 重试；收到 `luoke.error` 丢弃部分输出。
- "用户在等"只用于有人正盯着结果的单次请求；批量工作标后台；`allow_battery` 只用于用户亲手启动的批量工作。
- 交每个任务的评测集；对速度敏感的任务声明延迟要求。
- 声明自己的数据位置。和请求有关的提示在自己界面就地显示，不弹抢焦点的窗口；主控不可用时暂停相关功能并就地说明。自己的本机网页只听 127.0.0.1，校验随机 token 和 Host。
- **配件清单**（2026-10-12 与 luoke-mem 商定，按推荐定）：每个配件的 .app 里 `Contents/Resources/luoke-accessory.json`，主控安装、卸载、核对任务归属都读它。字段：

  ```json
  {
    "contract": 1,
    "accessory": "luoke-mem",
    "bundle_id": "ai.luoke.memory",
    "name": "螺壳记忆",
    "version": "0.6.0",
    "type": "component",
    "entry": ["-m", "luoke_mem", "app"],
    "resident": false,
    "memory": false,
    "ui_element": true,
    "tasks": [],
    "data": [],
    "commands": {
      "ui": ["-m", "luoke_mem", "--path", "{memory}", "ui"],
      "forget-tool": ["-m", "luoke_mem", "--path", "{memory}", "forget-tool", "{tool}"]
    }
  }
  ```

  `commands.uninstall`（可选，2026-10-16 与 luoke-mail 商定）：用户勾了"同时删除我的数据"时，在配件停掉之后、删文件之前用它自带的 Python 跑的数据收尾命令（不勾不跑：数据留着，钥匙串里的东西也留着）（邮件助手用它删钥匙串里的授权码：`["-m", "luoke_mail", "--forget-secrets"]`）；环境只给 PATH、HOME；退出码非 0 只提示不阻止。`commands.ui` 已没人用（主控 2026-10-16 删了转发端点），luoke-mem 在 beta1 后去掉。

  `accessory` 是配件标识（也是它在记忆里的工具标识）；`type` 取 `app`、`component`、`input-method`；`entry` 是打开 .app 时交给自带 Python 的参数（启动器只做 exec，不做别的；不是 Python 的配件——输入法——写 `[]`）；`resident` 是默认要不要常驻；`memory` 为 true 表示读写记忆（装它时一起装螺壳记忆）；`ui_element` 对应 `LSUIElement`；`tasks` 是 `[{"name": "luoke-mail.triage", "kind": "generate" | "score" | "predict" | "embed", "main": true | false}]`，任务参数不在这里、在配方里；`data` 是卸载时可删的数据位置（`~` 开头）；`min_macos`（可选，例如 `"26"`：这台 Mac 的 macOS 低于它时首次运行不列为可装、说明原因；输入法 26 起，luoke-ime 2026-10-15 定）；`commands` 只有组件配件填，占位符 `{memory}`（记忆文件路径）、`{tool}`（配件标识）由主控填，`forget-tool` 试跑时主控在末尾加 `--dry-run`。Python 配件的打包脚本（§10 第 5 项）从这份清单取 bundle id、名字、版本和入口，不另要参数。
- **清单的打包字段**（只给打包脚本看，主控不读）：`icon`（可选，2026-10-15 应 luoke-mail 的需求加）——.icns 文件，路径相对清单文件所在目录；打包脚本拷成 `Contents/Resources/AppIcon.icns` 并写 `CFBundleIconFile`。主控自己的图标放 `app/AppIcon.icns`（或 `LUOKE_ICON_FILE`），`app/build_app.sh` 同样处理。图标由 luoke-community 出稿、定（顶层 ADR 0017）。
- **打包脚本产出的布局**（`tools/package_python_app.py`，2026-10-12 按推荐定）：`<名字>.app/Contents/MacOS/<配件标识>` 是启动器（编译版，`tools/launcher/Launcher.swift`，2026-10-13 按 luoke-mail 提的需求做）：它作为 .app 的进程一直在，自带 Python 跑清单的 `entry` 当子进程，子进程退出它就退出；主控登录时拉起常驻配件会在入口后加 `--resident`，用户自己打开则没有；用户再次打开已在运行的 .app（程序坞、Finder、点通知）时，启动器再跑一次入口并加 `--reopen`（新进程，配件自己决定打开页面还是别的）；`<app>/Contents/MacOS/<启动器> --notify <标题> <副标题> <正文> [--open <参数>]` 以 .app 的名义发通知，点了通知就是一次 `--reopen`，参数经环境变量 `LUOKE_OPEN_ARG` 给入口；入口的环境里有 `LUOKE_LAUNCHER`（启动器路径，配件用它发通知）。Python 配件不要自己注册登录项或 LaunchAgent（§8 第二条）。`--launcher shell` 可以退回只 exec 的脚本；自带 Python 在 `Contents/Resources/python/bin/python3`（python-build-standalone 3.12，install_only，版本和哈希钉在脚本里）；配件的包装在它的 `site-packages` 里，所以 `-m <包>` 直接可用；清单在 `Contents/Resources/luoke-accessory.json`。打包时标准库和包都预编译成 `.pyc`。主控跑清单里的命令就是 `<app>/Contents/Resources/python/bin/python3 <commands 里的参数>`，环境只给 `PATH`、`HOME`，并设 `PYTHONDONTWRITEBYTECODE=1`（子进程也继承；往 .app 里写 `__pycache__` 会弄坏签名的封印，只加 `-B` 管不到配件自己再起的进程）。开发版 ad-hoc 签名；Developer ID 签名和公证在发布脚本里做（§11）。
- **启动器 `--notify` 的退出码**（2026-10-20 应 luoke-mail 加）：0 交给系统了；3 用户没允许通知（stderr 写 authorizationStatus 和 alertSetting）；4 系统拒收这条（stderr 写错误）；5 10 秒内系统没答复；64 用法不对。`--notify-status` 只打印一行 JSON `{"authorization", "alert"}`，不发通知、不请求授权。两者都要用 `.app` 里的启动器路径调，才是以这个应用的名义。
- **完成页显示各应用的通知状态**（2026-10-20，luoke-top 提：开发机上邮件助手的通知一直被系统拒、整个下午没收到提醒，测试者也会默默收不到；进 beta1 算修缺陷）：首次运行和升级的完成页对每个普通应用调它启动器的 `--notify-status`（旧启动器答不出就不列），已允许的写"通知已打开"；还没问过的给「允许它发通知」——以那个应用的名义发一条测试通知，系统先弹出允许询问；被拒或横幅关了的给「打开通知设置」，直达系统设置里那个应用的通知页（`x-apple.systempreferences:com.apple.Notifications-Settings.extension?id=<bundle id>`）。每 2 秒刷新，全部打开了就停。
- **空闲任务**（顶层 ADR 0014，2026-10-14 定；`luoke_core/jobs.py`）：任何配件都可以在清单里登记"空闲时跑"的命令，主控只决定什么时候跑、到时拉起、用户回来让它收尾，不知道也不管它做什么。清单字段 `jobs: [{"name", "command", "min_interval_minutes", "uses_model", "memory_mb", "allow_battery", "timeout_minutes"}]`：`command` 是给自带 Python 的参数（主控加 `-B`，占位符 `{memory}`、`{tool}` 同 `commands`），其余有默认值（120 分钟、true、100 MB、false、30 分钟）。可选字段 `exec`（2026-10-20 应 luoke-core#16 加，只加不改）：不带 Python 的配件（Swift 写的，例如 luoke-search）填 `Contents/MacOS/` 下的可执行文件名（不能带路径），这时 argv 是 `<app>/Contents/MacOS/<exec>` + `command`；没有 `exec` 照旧用 .app 自带的 Python 跑 `-B` + `command`。别的规矩一样。任务的 stderr 主控整段存在 `logs/jobs/`、4 KB 尾巴进 state.json（随诊断导出），**配件保证里面没有用户内容**；`GET /status` 里不带它（别的配件不该读到某个工具的输出，2026-10-16 自查后改）。主控什么时候起：安静时刻（5 分钟没有用户在等的请求）、后台状态 running（电源、低电量、过热、内存都允许；`allow_battery` 为 true 时电池上也行）、没有别的后台任务或空闲任务在跑、距上次启动够最短间隔；一次只跑一个。环境：`PATH`、`HOME`、`LUOKE_HUB_SOCKET`（经主控用模型就连它，请求用 `background` 优先级）、`PYTHONDONTWRITEBYTECODE=1`、`PYTHONNOUSERSITE=1`；cwd `/`；标准输出丢弃，标准错误写到主控 `logs/jobs/<配件>.<name>.stderr`、最后 4 KB 进 `state.json`（配件保证里面只有原因、没有内容）。收尾：用户回来（来了用户在等的请求）、别的配件的后台工作占着引擎（它自己发的后台请求和由此引起的底座加载不算；10-20 修：之前算，luoke-mem.learn 每次跑约 5 秒就被收掉）、后台状态变 paused、超过 `timeout_minutes`、主控退出 → SIGTERM，15 s 内没退就 SIGKILL；配件收到 SIGTERM 或请求被答 `busy` / `paused` / `interrupted` 就停在做完的那一步、退出码 0，没事可做也是 0，起不来非 0。记录：`state.json` 的 `jobs[<配件>.<name>]`（last_start、last_end、exit、reason：running / done / failed / wrapped_up / timeout / paused / hub_stopping、secs、stderr_tail），`/status` 里也有；主控日志只记这些元数据。新装、换装的配件一分钟内被看到。**派发上的优先**（2026-10-15，第一次真跑撞上邮件助手的后台系列才发现）：空闲任务跑着的时候，它那个配件的后台请求优先拿后台名额，功耗间歇照歇，但主控挂着等间歇过去、不拒绝（最多 4 分钟；10-25 负责人：静音档风扇猛转，原来免间歇时管不住它）；别的配件的后台请求收到 `busy`、`reason: "idle_job"`、`retry_after` 30 s，任务结束再接。`busy` / `paused` 的错误体都带 `reason`（interactive、scored_recently、not_quiet、engine_busy、power_cooldown、idle_job、memory、battery…），配件据此决定等还是退（luoke-mem 的 learn：interactive 就退，其余按 retry_after 等）。门口回绝的后台请求也记进主控日志（任务、配件、code、reason，只有元数据）。
- **能力声明**（顶层 ADR 0014，luoke-agent）：配件在清单里用 `capabilities` 声明能报什么事、能做什么（交互用 A2UI 描述）；字段内容和协议由 luoke-agent 和各配件商定，主控原样保存、不解释。2026-10-27 起 capabilities 只加不改，加了 `service`（基础页、概览、深页入口）和 `permissions`（工具要的权限，状态由工具自己照实报），主控照样不解释（顶层 ADR 0014 的 10-27 修订）；唯一的例外是装之前要看的介绍：发布流水线（`tools/release.py` 的 `listing_from`）把 `capabilities.listing` 的一句话、类别和 `permissions` 的说明抄进发布清单该项的 `listing`，大小由流水线实测、档位由配方定，配件自己写的 `size_mb`、`min_tier` 和权限的默认值、动作名都不抄。`GET /accessories`（2026-10-14 加，任何已验证的配件可调，luoke-agent 用它知道装了哪些工具）返回 `{"contract": 1, "accessories": [{accessory, bundle_id, name, version, type, resident, memory, tasks, capabilities, jobs（只有名字）}]}`，只给清单里的公开字段；主控只告诉装了什么，不替工具传话。luoke-agent 本身是主控安装的常驻配件（`type: app`，`resident: true`），用模型走任务层。和 luoke-agent 定下的（2026-10-15）：「螺壳.app」装在 `~/Applications`，bundle id `ai.luoke.agent`（开发版 `ai.luoke.agent.dev`），`memory: true`（自带一份 luoke_mem 读理解）；壳是 Swift 自己写的，不用打包脚本的编译启动器——清单 `entry: []`（和输入法一样），主控登录时经 `NSWorkspace` 打开它并带参数 `--resident`，异常退出就重启，它正常退出前调 `exiting`；再次打开就是普通的 reopen；通知由它自己发（它是唯一主动找用户的出口，顶层 ADR 0014）。Python 核心借主控自带的 Python（上一条的约定，`-B -E -s`）。`capabilities` 按它的工具协议原样保存。模型任务以后再进配方：`luoke-agent.chat`（generate，用户在等；选工具用 `response_format` 的 JSON schema 输出，推理字段白名单里没有 `tools`）、`luoke-agent.brief`（generate，后台），到时交评测集。
- **主控自带的 Python 可以借**（2026-10-14，应 luoke-ime 的需求、负责人提的做法）：`螺壳主控.app/Contents/Resources/python/bin/python3`（python-build-standalone 3.12，完整标准库含 sqlite3，和主控同一个 Team 签名、hardened runtime；`python3` 是指向同目录 `python3.12` 的符号链接）。配件按 bundle id `ai.luoke.core` 找到主控，在自己的沙盒里只读地起它跑只用标准库的代码（输入法的个人化组件），设 `PYTHONDONTWRITEBYTECODE=1`，建议再加 `-B -E -s`（不读用户的 `PYTHON*` 环境变量和用户 site-packages；它的 site-packages 里只有 luoke_core）。主控保证：契约 1 内这个路径和 bundle id 不变；换 Python 大版本（3.12 → 3.x）前先写进注册页并通知用它的配件；小版本随主控发布车更新，不另通知。找不到主控时配件自己退化（输入法：没有个人化组件，打字照常）。

## 9. 数据边界、日志

- 底线按顶层 ADR 0013（2026-10-14）：工具和模型只在用户的 Mac 上运行，数据只在用户自己的设备之间流动、端到端加密，不依赖能读到内容的云服务；主控本身不联网（下载模型和引擎包除外）。以后的"远端引擎"（[research/remote-engine.md](research/remote-engine.md)）套用这条时，请求文字会出现在远端设备的内存里，到时单独定。
- 本机组件之间不为隐私设限（顶层 ADR 0013）。下面几条的理由是：日志和缓存不是存内容的地方，诊断会出本机，oMLX 的 SSD 缓存实测命中 0%。
- 请求文字及其派生物只在内存里。主控日志只记元数据；异常和崩溃报告经去内容过滤。空闲任务的标准错误由配件保证不含内容。
- 标记字符串测试（生成和打分各一条）覆盖正常完成、格式不合法、超长输入、打断、内存保护拒绝、引擎异常，确认主控日志、`{base_path}/logs`、缓存目录、工作进程输出、崩溃报告里都没有标记。不通过的引擎包版本不进配方。
  - 开发版的测试程序：`tools/privacy_marker_test.py`（2026-10-12）。对着 oMLX 0.7.0，日志级别 warning 和 info 都通过：正常完成、JSON 约束、格式不合法、超长输入、后台被打断、打断时的"用户在等"、打分，主控环境和引擎 base_path 下逐字节没有标记（含 usage.sqlite3、stats.json、settings.json、cache/、logs/、cluster/）。所以引擎包的日志级别定 info（它只记 token 数和耗时）。内存保护拒绝和请求进行中引擎崩溃也覆盖了（同日）：实验室构建多两个故障端点 `POST /lab/ceiling`、`POST /lab/engine/kill`（正式构建没有），测试里把天花板降到底座放不下（返回 needs_user）、再在请求中杀自己起的引擎（engine_failed，主控随后重启），两条路上也没有标记。顺手改的：引擎的错误体不再进主控日志（只记 `status_<码>`），因为它可能引用请求文字。没测 debug 级别（没必要）。
- 默认不上报。诊断信息只含机型、芯片、内存、档位、版本、任务状态、冒烟结果和速度、错误码、崩溃摘要，不含请求文字及其哈希。
- 看进程列表了解其他引擎的内存占用；复用模型时只读、只克隆用户引擎的模型文件（§6），不改用户引擎的文件和设置。
