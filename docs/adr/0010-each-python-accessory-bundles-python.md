# 每个 Python 配件自带一份 Python，不用共享的配件运行时

v0 定的是主控环境里带一份由实验室固定版本、签名公证的共享 Python（"配件运行时"），所有 Python 配件共用。设计审查指出它是又一个要单独签名、分发、更新和验证的组件：升级它会同时改变所有 Python 配件的行为（例如 luoke-mail 解析邮件），而证据里没有记录它的版本。改为每个 Python 配件在自己签名公证的 .app 里自带一份 Python（例如 python-build-standalone），这份 Python 的版本自然跟着配件版本走，也就自动被那个配件版本的评测覆盖。代价是每个配件多出几十 MB。

## Considered Options

- **共享的配件运行时**：推到以后，等 Python 配件多到磁盘占用值得共享时再考虑。
- **沿用引擎包里 oMLX 的 Python**：否决，引擎包一升级，luoke-mail 的运行环境也跟着变。
- **继续用 `/usr/bin/python3`**：否决，干净的 Mac 上它会要求先装命令行开发者工具。

## Consequences

- 放宽 v0 的"配件只用标准库"：配件尽量只用标准库；确实需要第三方包时，随配件 .app 签名打包、版本固定，由该配件版本的评测覆盖。
