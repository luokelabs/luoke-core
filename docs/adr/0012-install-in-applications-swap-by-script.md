# 装进 /Applications，升级换包交给独立的小脚本，写不进去时才要管理员授权

负责人 2026-10-24 定（luoke-core#30，beta1 前做完）。原来主控装在 `~/Applications`（ADR 0002）：DMG 里双击，主控把自己拷过去。大多数 Mac 应用的做法是 DMG 窗口里拖进「应用程序」，用户也是这么认的。改为：

- **安装位置**：DMG 窗口里左边「螺壳」、右边「应用程序」的快捷方式，拖过去就装在 `/Applications/螺壳.app`。主控**以实际所在位置为准**：`/Applications`、`~/Applications` 两处都认，新旧名字（螺壳 / 螺壳主控）都认，只认 bundle id 和自己一样的。升级、回退、命令行链接、登录项都跟着它实际所在的位置走。
- **首次打开**：在「应用程序」里第一次打开，进首次安装；从 DMG 里直接双击「螺壳」，提示先拖进去，另给一个「帮我装进去」的按钮（照旧自己拷过去）。应用的安装器（`安装邮件助手.app` 这类）照旧双击就装，不改。
- **升级换包交给独立的小脚本**：主控（检查更新）或安装器先把新版拷到环境目录的暂存处、核对签名、卸掉 DMG，再起一个 `/bin/sh` 小脚本，然后自己退出。脚本等它退出，把旧版挪进 `previous.noindex`、新版换上，再用 `/usr/bin/open` 起新版。新版不再是"主控以同一个 bundle id 再起一个安装器实例"：那样每一层都把上一层记成父进程，旧的死图标挂在程序坞上（10-24，macOS 27）。
- **写不进去时才要管理员授权**：/Applications 归 root:admin，管理员账户能直接写，不弹任何东西。标准账户写不进去，升级时把上面那个脚本交给系统标准的管理员授权框（`osascript … with administrator privileges`）去跑；授权框在主控退出之前弹，用户取消就什么都不动，主控照常用。脚本里用 root 只做换包这两步，起新版时切回用户身份（`launchctl asuser`）。不装特权辅助程序，没有常驻的 root 进程。
- **迁移**：原来装在 `~/Applications` 的，升级时搬进 `/Applications`；写不进去（标准账户、或授权被拒），就留在原处照常升级，不强迫。
- **应用（邮件助手等）不搬**：照旧由主控装在 `~/Applications`。它们由主控替用户装、替用户升级，放进 /Applications 的话，标准账户每升一次应用都要授权。

## Considered Options

- **保留 `~/Applications`、DMG 里的快捷方式指过去**：不用授权，但用户很少见到个人的「应用程序」文件夹，拖错地方的多。负责人选了 /Applications。
- **特权辅助程序（SMAppService daemon）**：标准账户升级也不弹框，但要单独签名、用户要在系统设置里批准一次、常驻一个 root 进程，三天里做不稳，也和 ADR 0007"不拿 root"的理由冲突更大。否决。
- **标准账户一律装在 `~/Applications`**：最省事，但用户拖进 /Applications 时 Finder 已经要过一次管理员密码，装完我们再挪走，反而奇怪。否决，改为"装在哪就在哪升级"。
- **安装器以新实例接管换包（原来的做法）**：留死图标（见上），而且换包和退出纠缠在两个同 bundle id 的进程之间。否决。

## Consequences

- ADR 0007 的"从不申请管理员权限"放宽一处：标准账户把螺壳装在 /Applications 时，主控升级、回到上一版要一次管理员授权。别的照旧：不装特权程序、不常驻 root，"不调 wired 内存上限"仍然是结构上做不到。
- 管理员账户（个人 Mac 的绝大多数）体验不变：不弹框。
- 一台 Mac 上可能同时有 `/Applications/螺壳.app` 和 `~/Applications/螺壳.app`（老用户拖了新的进去）：主控按 bundle id 认，新版起来后把另一份挪进 `previous.noindex` 并注销，不留两份。
- 系统的「App 管理」权限：同一开发者签名的应用替换自己，系统不拦；由 root 脚本替换时算不算"自己替换自己"，要实测（10-27），不行就退回"标准账户留在 `~/Applications`"，到时补修订。
- 配件找主控（邮件助手、输入法）要两个位置都认：luoke-mail 0.18.3、luoke-ime 0.1.14 起已经这样。

## 修订（2026-10-25，标准账户不测）

负责人 10-25 定：标准账户那条路（管理员授权框）beta1 前不测。个人 Mac 基本都是管理员账户；这条路就算有问题，也只是升级失败、旧版照常能用。授权框的代码留着，有测试者反馈再测再修；测试说明写"请用管理员账户安装"（luoke-community）。管理员账户的三种换包（从 ~/Applications 搬进 /Applications、原地升级、检查更新）10-25 在 16 GB 测试机（M1）上用开发版实测过。
