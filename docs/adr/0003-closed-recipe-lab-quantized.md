# 配方封闭：只用实验室评测过、自己量化的模型，没有逃生门

主控只使用配方里的模型和任务；用户和配件都不能加入配方外的模型，也没有隐藏的开发者模式。配方里的模型由实验室从上游官方权重自己量化，发布在实验室自己的 Hugging Face 和 ModelScope 同名仓库，以文件哈希为准；许可不清楚的模型不收；配方经签名、只增版本。理由：螺壳做的是精品，承诺的是"这个文件 + 这个引擎 = 这个结果"，只有封闭才能由实验室兜底；从封闭改开放容易，从开放收回会伤到已有用户；代码开源，真想 hack 的人可以自己改。

## Considered Options

- **开发者模式逃生门（Mac 式）**：否决，"未经评测"的状态会渗进每个界面、对照表和用户反馈。
- **开放，配方只作推荐**：否决，等于放弃质量保证。
- **直接引用社区量化仓库**：否决，那些仓库没有 license 字段、随时可能删库，证据无法复现。

## Consequences

- 现有证据（建立在社区量化上）进配方前要按新格式重测。
- 国内用户经 ModelScope 下载，不需要自建 CDN 或备案。

## 修订（2026-10-09，设计审查后）

- 实验室自己开发和调试要有路可走，但不能在正式构建里留开关：定义"实验室构建"——不同的 bundle id，独立的主控环境和 socket 路径，可以运行未验证的配件版本，不对外分发；正式构建不编译这些代码路径。第一版的配方不签名，实验室构建直接从自己的主控环境读本地配方；v1.x 配方开始签名后，改为内置实验室测试公钥、对本地配方验签，而不是关掉验签。
- 第一版只开一个下载通道（以国内用户为主用 ModelScope），配方里的下载地址写成列表、以哈希为准，Hugging Face 同名仓库在 v1.x 加上。
- 上文"配方经签名、只增版本"在第一版不成立：第一版的配方随主控 .app 发布（ADR 0009），完整性由代码签名和公证保护，主控不拒收比本地旧的配方（否则用户装不回旧版主控）；签名和"只增版本"随 v1.x 的独立配方通道一起生效。签名私钥不再"离线保管"，改放在硬件密钥或 Secure Enclave 里（DESIGN §10）。
- 上文 Consequences "不需要自建 CDN 或备案"只对模型文件成立。主控、配件、引擎包和更新源（含撤回清单）的托管另定；国内能否访问、要不要备案，见 DESIGN §13 第 1 项。
