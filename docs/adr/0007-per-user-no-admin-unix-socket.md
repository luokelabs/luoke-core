# 只按用户安装、不要管理员权限，任务层只开在本账户的 Unix socket 上

主控、引擎、模型和配件全部装在当前账户下（~/Applications、用户级登录项、~/Library/Application Support 下的主控环境），从不申请管理员权限、不装特权辅助程序；任务层只开在主控环境里一个只有本账户能进的文件夹（0700）里的 Unix domain socket 上，报文仍是 OpenAI 兼容的 HTTP，配件凭安装器发的令牌表明身份。理由：绝大多数 Mac 只有一个人用，不值得为多账户共享引入特权进程；不拿 root，"永不调高 wired 内存上限"就从承诺变成了结构上做不到（2026-09-29 曾因调高该上限导致内核崩溃）；127.0.0.1 端口全机共享，可能被其他账户或进程抢先占用、收走邮件正文和打字内容，网页也可能借 DNS rebinding 访问，socket 从结构上消除了这两种风险。

## Considered Options

- **按整台机器安装、模型全机共享**：否决，需要管理员权限和跨账户的特权进程。
- **127.0.0.1 TCP 端口 + 令牌**：否决，见上。
- **XPC**：否决，Python 配件很难用。

## Consequences

- 一台 Mac 的多个账户各存一份模型；别的账户的占用按"其他 AI 引擎"计。
- Swift 配件（jiu）要用 Network 框架写一个连 socket 的小客户端；Python 配件用 `http.client` 子类即可。
- 主控环境与 ~/.luoke 等配件的用户数据分开，清理主控环境不会删掉用户的记忆。

## 修订（2026-10-09，设计审查后）

- 第一版去掉配件令牌：令牌本来就不是安全措施（本账户的进程都能读到令牌文件），只多出签发、保存、重发几个故障点。配件在请求头里自报标识和版本，主控按配方的任务表核对任务归属；未登记的调用方不受支持，以后可能失效（以后如需按配件授权，再考虑基于代码签名的调用方身份）。Unix socket 不变。
- 连 socket 的是配件里的 Python 部分（jiu 的判断逻辑也在 Python 进程里），用 `http.client` 的子类即可；只有以后出现要直接连 socket 的 Swift 部分，才需要用 Network 框架写客户端。
- 上文"别的账户的占用按'其他 AI 引擎'计"在第一版的做法：进程列表里看得到的其他账户的引擎进程，按其他 AI 引擎计入预算；按账户归因并告诉用户，以后再做。

## 修订（2026-10-10，jiu 由螺壳输入法取代）

jiu 已由螺壳输入法取代，上一段修订里"连 socket 的是配件里的 Python 部分"不再成立：输入法里连主控 socket 的是它的壳（Swift，不在沙盒里），要用 Network 框架写客户端；输入法的引擎在 Seatbelt 沙盒里，沙盒对任何 unix socket 都不放行，它们的请求经壳转发。

## 修订（2026-10-24，主控装进 /Applications）

主控本体改装在 /Applications（ADR 0012，负责人 10-24 定）。"从不申请管理员权限"放宽一处：标准账户的 /Applications 写不进去，主控升级、回到上一版时，换包那两步交给系统的管理员授权框去跑。仍然不装特权辅助程序、不常驻 root 进程；引擎、模型、配件、socket 都照旧在本账户下。
