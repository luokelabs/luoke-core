# 现有配件对主控的需求与接入要点

> 参考资料，不是核心设计。主控的设计（[DESIGN.md](../DESIGN.md)）不针对任何具体配件；现有配件只是需求的来源。2026-10-10 起，每个配件对主控的需求也登记在螺壳顶层各自的注册页（`~/Codes/luoke/projects/`），由配件自己维护，和这里不一致时以注册页为准。早期的配件 jiu 已由螺壳输入法取代，下文按输入法重写。这里记录两件事：现有配件的哪些具体需求催生了主控的哪些通用机制；这些配件要接入主控，各自要做哪些改动。具体数值（门槛、延迟要求等）最终写进配方的任务表，接入工作在配件自己的仓库里做。整理于 2026-10-09，取自 DESIGN v0.1 初稿 §11 以及设计审查。

## 需求来源一览

| 主控的通用机制 | 主要来自哪个配件的需求 |
|---|---|
| 打分任务、专用模型、打分端点（不等待加载） | 螺壳输入法：打字时每个键都可能要在几十毫秒内给十几个候选算 log 概率（最早来自 jiu） |
| 交互中判定、后台让路、打分任务与后台共存的备选做法 | 输入法的打字间隙和 luoke-mail 的后台批量分拣争 GPU |
| 后台请求、功耗档、电池规则、`allow_battery` | luoke-mail 的后台整理、用户亲手点的"整理全部" |
| 任务参数里的条目数、每条目预算、批大小、字符上限 | luoke-mail 一次请求处理多封邮件、按行数估算输出长度 |
| 任务参数里的门槛和奖励常数 | 输入法重排的门槛 τ（单位是模型的 nats；jiu 时还有 `BONUS_HARD`、`BONUS_SOFT`） |
| 常驻配件（`PUT /accessory/resident`） | luoke-mail 开启自动整理时常驻（输入法由系统的输入源机制拉起，不用这个机制） |
| 预热租约 | luoke-mail 界面打开时，用户随时可能点"起草回复" |
| 报告正常、迁移前快照 | luoke-mail 的数据库只有正向迁移 |
| 配件声明自己的数据位置 | luoke-mail 的数据目录、钥匙串里的授权码（记忆库不算任何配件的数据，顶层 ADR 0002） |
| 配件的 bundle id、Team ID、安装路径一旦发布不变 | 输入法的 bundle id 或安装路径一变，用户要重新在系统设置里添加输入源（jiu 当时是辅助功能和输入监控授权） |
| 配件自己的本机网页要校验 token 和 Host | luoke-mail 的本机网页 |
| 请求文字不落盘、诊断信息不含文字哈希 | 输入法看到的是用户打的每一个字，短文本的哈希能被字典穷举 |

## luoke-mail

**它对主控的需求**
- 后台批量分拣（AutoSync 循环）和用户点按钮触发的单次调用（例如起草回复）并存。
- 9 类任务（以 `~/Codes/luoke/projects/luoke-mail.md`「对主控的需求」为准）；目前只有分拣有评测集（45 封，含 13 封钓鱼；硬性条目2026-10-11 定为正常邮件 0 误报、可疑最多漏 1 封），其余 8 类没有评测集就进不了配方（DESIGN §7）。
- 一次请求处理多封邮件，输出长度按条目估算；输入可能很长，需要按上限截短。
- 开启自动整理时需要常驻；界面打开时希望底座已加载。
- 数据：`~/.luoke-mail/`、钥匙串里的邮箱授权码。记忆库 `~/.luoke/mem.db` 不是它的数据：记忆归用户、由 luoke-mem 管（顶层 ADR 0002，2026-10-10），卸载 luoke-mail 不删记忆，它写进记忆的东西要不要忘掉由用户在卸载时单独选。

**接入要做的改动**
- 打包成签名公证的 .app，自带 Python，取代现在 ad-hoc 签名的 AppleScript 启动器和 LaunchAgent。迁移时 `launchctl bootout` 旧的 `local.luoke-mail` 服务，删除旧启动器。用户开关自动整理时调用 `PUT /accessory/resident`。
- 系统通知由 luoke-mail.app 自己发出（包里带一个签名的通知 helper，或由 .app 主程序代发），取代原来由启动器转发的做法；点开通知打开本机网页。
- 本机网页保留现有的随机 token 和 Host 校验。界面打开时发起预热、开着期间续期。启动时做完数据迁移后调用 `POST /accessory/ready`（迁移前把 `~/.luoke-mail/` 下的库做快照；`mem.db` 的迁移和快照归 luoke-mem）；正常退出前调用 `POST /accessory/exiting`。
- 模型调用改走任务层：后台调用标"后台"，收到 `busy`、`paused` 或 `interrupted` 时按 `retry_after` 重试，保留 AutoSync 循环；用户点按钮触发的单次调用标"用户在等"。
- 删掉今后归主控的东西：功耗节流（`engines._rest`、`set_power` 和设置页的功耗项）、内存退避（`full_for`）、idle 任务的串行等待、"换用较小的模型"文案、由内存报错触发的截短重试。输入截短改为按 `GET /tasks` 给的字符上限做（v0 曾计划删掉全部截短逻辑，但主控对超长输入直接拒绝，配件又数不了 token）；批量请求按批大小分批，在请求里报条目数。`RECOMMENDATIONS` 改为从 `GET /tasks` 读。
- 只上线有评测集的任务：每个任务补一个 20–40 条起的评测集（含硬性条目，可以由 AI 代理起草、负责人审核）；分拣的评测集补一批"从没被拿来调过提示词"的真实难题。
- v0 曾计划把它的后台工作改成"后台入口 + 按计划叫醒"；v0.1 改为保持常驻、保留 AutoSync，后台入口推到以后。

## 螺壳输入法（luoke-ime）

取代了早期的 jiu（上屏后纠正同音字）：jiu 的做法已经并进输入法的引擎，打字时就按前文选出首选，不再等上屏后去改。现状数据见 [ime-现状.md](ime-现状.md)；它对主控的需求以螺壳顶层的注册页 `~/Codes/luoke/projects/luoke-ime.md` 为准。

**它对主控的需求**
- 打分任务（重排）：给定前文和 10–15 个候选整句，返回 log 概率。一次重排逐词做 1–9 次打分，每个键都可能触发一次重排；需要前缀缓存（同一句里"前文 + 已定的词"反复出现，现在保留最近 16 条前缀快照；主控已接，2026-10-11，DESIGN §4：打分工作进程按配件留前文 KV 快照，条数是任务参数）；用户敲了下一个键就取消（关闭连接）。
- 延迟要求（写进配方任务表，数值待实测后定）：实验室关卡是"最后一个键到重排结果"的端到端时间，按 120 ms 一个键的逐键评测计；不经主控时在 32 GB 测试机（基础款 M4）上实测中位数 122 ms、p90 186 ms，壳在按空格时最多再等 150 ms。本机阈值是对应的单次打分 p90。
- 以后：联想（上屏后给接着写的候选打分排序，同样是打分任务）；语音识别（DESIGN 里"以后"的一直加载的小模型）。
- 任务参数：重排的门槛 τ（nats，现在是 3）。
- 主要任务和可选任务：输入法的主要功能（出候选、上屏）不依赖 AI，重排和联想都是可选任务；主控不可用或返回 `not_ready` 时照常输入，只是没有重排。
- 看到的是用户打的每一个字，请求文字不落盘、不进日志对它最要紧。

**和现有机制不完全对上的地方**（2026-10-10 已定，落实在 DESIGN §11、V1 §8；每条末尾是结论）
- **安装位置和启用**：输入法装在 `~/Library/Input Methods/`，不在 `~/Applications`；装好后要引导用户去系统设置手动添加输入源（macOS 26 起，不添加就用不了）。 → 接入契约改为"安装路径由配件类型决定，发布后不变"；主控装完输入法后引导用户去系统设置添加输入源。
- **启动和保活**：由系统的输入源机制拉起，崩溃后由系统重新拉起；不经主控、不是常驻配件，主控的常驻声明和异常退出计数对它不适用。 → 新增"系统拉起的配件"一类：不声明常驻、不计异常退出，主控不管它的生命周期。
- **连 socket 的是 Swift**：只有输入法的壳（Swift，不在沙盒里）能连主控的 socket；它的输入法引擎在 Seatbelt 沙盒里（unix socket 一律不放行），请求经壳转发。对主控来说配件只有一个身份。这和 ADR 0007 修订里"连 socket 的是配件里的 Python 部分"不同，壳要用 Network 框架写客户端。 → 契约不限语言，ADR 0007 修订已写明；不再改。
- **打分请求很密**：打字时每个键都可能有一串打分请求，"交互中"会一直被刷新；后台工作要让路得更彻底（DESIGN §6 做法 1 的 K 分钟窗口可能就够）。 → 由实测 0（docs/experiments/coexistence.md）的结果定让路做法。

**接入要做的改动**（在 luoke-ime 仓库里做）
- 壳加连主控 socket 的客户端（Swift，Network 框架），以及让输入法引擎经壳提请求的"转问"；配件标识 `luoke-ime/<版本>`。
- 输入法引擎自带的打分进程（`engines/xiaohe/scorer.py`）去掉，改由输入法的个人化组件经壳调主控的打分任务（见输入法 `docs/设计.md` 的"个人化与联想"）。
- 门槛 τ 改从 `GET /tasks` 读。
- 打分请求标"用户在等"；收到 `not_ready` 就只用快的候选；收到 `needs_user` 时在输入法菜单里说明原因和占用者（不弹窗）。
- 评测集：博客 600 条的重排评测（`engines/xiaohe/bench.py`），按主控的证据格式补齐，并加上硬性条目。
- bundle id `ai.luoke.inputmethod.Luoke`、Team ID、安装路径 `~/Library/Input Methods/LuokeIME.app` 保持不变（变了用户要重新在系统设置里添加）。

## luoke-mem

- （已被顶层 ADR 0003 取代：第一版就作为配件安装。）原计划随 luoke-mail 发布；"从邮件中了解你"等推断属于 luoke-mail 的任务，评测集由 luoke-mail 提供。
- 主控第一版就把它当组件配件安装（顶层 ADR 0003）：「螺壳记忆.app」，bundle id `ai.luoke.memory`，没有模型任务、不交评测集；打开 .app 即打开整份记忆的界面；卸载别的配件时主控用它跑 `forget-tool`。`~/.luoke/mem.db` 归用户、由 luoke-mem 管，不归任何配件（顶层 ADR 0002）。细节见 DESIGN §8、§11。
